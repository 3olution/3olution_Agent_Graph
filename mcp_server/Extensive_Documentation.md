The compatibility shim in _server.py
The mcp Python SDK changed its public API between major versions:

SDK version	Class name	Import path
1.x	FastMCP	mcp.server.fastmcp
2.x (early)	MCPServer	mcp.server
2.x (current)	MCPServer	mcp.server.mcpserver
_server.py tries the 2.x canonical path first, then the early-2.x
alternate, then falls back to 1.x. That means the same tool files
work against any currently-installed SDK without modification.

If none of the three imports succeed, the module raises an
ImportError with a specific, actionable message naming each
expected import path and pointing at pip install 'mcp>=2.0.0'.

The Windows event loop fix
The subtle bug this avoids:

Python 3.8+ on Windows defaults to ProactorEventLoop.

Proactor supports asyncio.create_subprocess_exec but has known
bugs reading from child process pipes.

FastMCP's stdio transport continuously reads from its own stdin
pipe.

Result: the initial MCP handshake hangs ~20% of the time.

Setting WindowsSelectorEventLoopPolicy before importing FastMCP
switches to SelectorEventLoop, which has reliable pipe support.
The MCP server does not need create_subprocess_exec itself — it
only reads and writes its own stdio — so the trade-off is free.

The policy must be set before the SDK import. _server.py
enforces this ordering by placing the asyncio.set_event_loop_policy
call above the from mcp... import ... block.

The banner suppression
FastMCP 1.x and MCPServer 2.x both print a Rich-rendered startup
banner to stdout unless told otherwise. The banner contains
box-drawing characters:

text
╭─────────────────────────────────────────╮
│                                          │
│   ███╗   ███╗ ██████╗██████╗             │
│   ...
Those characters are not valid JSON. If the banner appears before
the first JSON-RPC message, the backend's stdio reader tries to
parse it and fails — producing a "Connection closed" error on the
backend side and an apparently silent server.

run() calls mcp.run(show_banner=False) to suppress it. Older SDK
versions do not accept the show_banner kwarg and raise TypeError;
the except TypeError fallback calls plain mcp.run() and accepts
the banner.

Tool inventory
After this batch, the MCP server exposes nine tools:

Module	Tool	Signature
math_tools	add	(a: float, b: float) -> float
math_tools	multiply	(a: float, b: float) -> float
math_tools	sqrt	(x: float) -> float
math_tools	power	(base: float, exponent: float) -> float
time_tools	current_time	() -> str
filesystem_tools	list_directory	(path: str = ".") -> str
filesystem_tools	read_file	(path: str, max_bytes: int = 4096) -> str
text_tools	word_count	(text: str) -> dict
text_tools	shout	(text: str) -> str
The JSON schemas are generated by the MCP SDK from the function
signatures and docstrings. word_count's return type dict becomes
{"type": "object"} in the schema; the LLM receives it as a JSON
string when called.

Loader pattern
The tool loader in tools/__init__.py mirrors the custom-node
loader in backend/graph/custom_nodes/__init__.py. Same naming
convention, same per-module try/except, same "drop a file and
restart" workflow. Learning one means knowing the other.

text
tools/
    __init__.py         ← loader, runs at import time
    README.md           ← documentation
    math_tools.py       ← auto-loaded
    time_tools.py       ← auto-loaded
    filesystem_tools.py ← auto-loaded
    text_tools.py       ← auto-loaded
    _helpers.py         ← skipped (leading underscore)
    __pycache__/        ← skipped (not a .py file at the top level)
Skipping rules:

Pattern	Action
*.py (top level)	Loaded
_*.py	Skipped
__init__.py	Skipped (implicitly, via the _ check)
__pycache__/	Skipped (not matched by glob("*.py"))
Adding a new tool — end to end
Create mcp_server/tools/units_tools.py:

python
from .._server import mcp

@mcp.tool()
def km_to_miles(km: float) -> float:
    """Convert kilometers to miles (1 km ≈ 0.621371 mi)."""
    return km * 0.621371
Restart the backend:

text
python run.py backend
Watch the backend log for:

text
INFO | Loaded MCP tool module: units_tools
INFO | MCP tool loader: 5 loaded, 0 failed
INFO | Spawning MCP server: ... -m mcp_server.server
INFO | MCP session initialised
Ask the chat UI: "How many miles is 5 kilometers?"

The agent will:

send the tool schema to the LLM

receive a tool_call for km_to_miles(5)

invoke the MCP tool

receive 3.106855

answer "5 kilometers is about 3.1 miles."

No changes to server.py, _server.py, tools/__init__.py, or any
other file are needed.

Testing a tool in isolation
To verify a tool module imports cleanly without starting the whole
server:

bash
python -c "import mcp_server.tools.math_tools; print('OK')"
To test a specific tool function directly:

bash
python -c "
from mcp_server.tools.math_tools import add, sqrt
print(add(2, 3))
print(sqrt(144))
"
The tool functions are ordinary Python functions. The @mcp.tool()
decorator attaches metadata but does not change the call signature.
