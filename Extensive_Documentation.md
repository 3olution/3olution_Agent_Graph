Setup wrappers (setup.sh / setup.ps1)
These are the two-command bootstrap for end users. They find any Python 3.8+ on PATH and hand off to bootstrap/setup.py, which downloads the portable runtime.

Launchers (start.sh / start.bat)
The launchers use the portable runtime, running the backend on the portable Python interpreter. They auto-run setup if the runtime is missing.

The PATH trick
Both launchers prepend runtime/python/bin and runtime/php to PATH before handing off to the backend. This means any subprocess the backend spawns — including the MCP server, PHP-CGI, and any future tool — will resolve python and php to the portable binaries rather than any system install.

Flags
Flag	Effect
--host HOST	Bind address (default 127.0.0.1)
--port PORT	Bind port (default 8000)
--reload	Enable uvicorn auto-reload
--help	Show usage
Custom port example
bash
./start.sh --port 9000
# Backend now at http://127.0.0.1:9000
.gitignore — what's ignored and why
Everything in the ignore list falls into one of five buckets:

Bucket	Examples	Why
Generated by bootstrap	runtime/	300 MB of binaries, re-downloadable
Downloaded at runtime	web/vendor/, models/	Network-fetched; large
Written by the app	logs/, sessions.db, php_app/data/*.db	User data
User-specific	.env, .vscode/	Not portable
OS clutter	.DS_Store, Thumbs.db	Not code
The rule: if it can be regenerated from code + .env + bootstrap/setup.py, it goes in .gitignore.

Whitelisted exceptions
text
!runtime/.gitkeep
!runtime/README.md
!models/README.md
!web/vendor/.gitkeep
These keep the empty directory structure in git while ignoring the (large, regeneratable) contents.

.env.example — the configuration contract
The .env.example file is the canonical list of every setting the app understands. It is committed; .env is not.

How config flows
text
.env.example  ─copy─→  .env  ─read─→  backend/config.py  ─inject─→  everything
backend/config.py uses pydantic-settings with env_prefix="AGENT_". Any variable in .env starting with AGENT_ becomes a field on Settings. Unknown variables are silently ignored (extra="ignore").

Default values
Every setting has a working default in config.py. A user can delete their entire .env and the app still runs — against a local Ollama instance with the model deepseek-r1:1.5b. That is the correct default for the target audience.

The two LLM provider configurations
The .env.example deliberately presents two LLM configurations that are easy to confuse:

Block	Purpose	When used
AGENT_LLM_*	Primary endpoint	Default route for every chat
AGENT_OLLAMA_HOST	Ollama native API	Settings page only (list/pull/delete models)
The first points at http://localhost:11434/v1 (OpenAI-compatible). The second points at http://127.0.0.1:11434 (native). Same server, different paths. The .env.example documents this explicitly.

requirements.txt — dependency notes
Four categories of dependencies:

Category	Packages	Optional?
Core web stack	fastapi, uvicorn, pydantic	Required
LLM client	openai	Required
MCP SDK	mcp	Required
Desktop	PyQt6, PyQt6-WebEngine	Optional (skip if browser-only)
Utilities	httpx, websockets, loguru	Required
Optional on-demand	llama-cpp-python	Installed from the UI
llama-cpp-python is deliberately NOT in requirements.txt. It has platform-specific wheels (CPU / CUDA 11.8 / 12.1 / 12.4) that must match the user's GPU drivers. Bundling it in requirements.txt would force a source build on machines without a matching wheel, which usually fails. Instead, backend/llama_installer.py detects the GPU and streams the correct pip install from the Settings page.

run.py — the developer workflow
run.py is the entry point for people working on the code. It uses a standard .venv/ and the developer's own Python, not the portable runtime.

Command summary
Command	What it does	Needs backend running?
setup	Create .venv/, install deps, download vendor	No
backend	Start FastAPI on 127.0.0.1:8000	No
desktop	Start PyQt6 client with embedded Chromium	Yes
native	Start PyQt6 client with native widgets	Yes
mcp	Run MCP server in the foreground	No
vendor	Force re-download LiteGraph files	No
Why scripts/serve.py and not uvicorn directly?
serve.py handles three things that would otherwise require the user to remember them:

Windows event-loop policy. Uvicorn creates the loop before importing the app, so setting asyncio.set_event_loop_policy() inside backend/main.py is too late. serve.py sets it before importing uvicorn.

sys.path for the reloader. uvicorn --reload spawns a child process. On Windows, the child uses multiprocessing spawn, which does not inherit sys.path mutations. serve.py sets both sys.path and PYTHONPATH.

loop="asyncio". uvicorn's default loop auto-detection sometimes picks uvloop, which does not always work with the MCP SDK's stdio transport. serve.py forces asyncio.

Python version gate
run.py refuses to run on Python < 3.10 with a clear error:

text
✗ Python 3.10+ is required. You are running 3.9.
This is because the code uses X | Y type hints (3.10+), asyncio.to_thread (3.9+), and pydantic v2 patterns that need a modern interpreter.

pyinstaller.spec — packaging the desktop client
What the spec produces
A single-folder distribution:

text
dist/
└── 3olutionAgentGraph/
    ├── 3olutionAgentGraph          (or .exe on Windows)
    ├── _internal/                  (Python runtime, Qt, DLLs)
    │   ├── PyQt6/
    │   ├── backend/
    │   ├── mcp_server/
    │   ├── web/
    │   ├── python312.dll           (Windows)
    │   └── ...
    └── .env.example
What's bundled
The full backend/ package, so the desktop client can spawn the backend as a subprocess

The mcp_server/ tools

The entire web/ tree (chat, graph, settings)

The scripts/serve.py entry point

Every hidden import PyInstaller can't discover statically

What's excluded
Excluded	Reason
tkinter	Not used
matplotlib, numpy, scipy, pandas	Not used
PyQt6.QtQuick, PyQt6.QtQml	Not used (we use QtWidgets)
PyQt6.Qt3DCore and friends	Not used
pytest, IPython, jupyter	Development only
These exclusions cut roughly 150 MB off the final bundle.

Size expectations
Component	Compressed	Extracted
PyQt6 + Qt6 core	40 MB	120 MB
PyQt6-WebEngine (Chromium)	120 MB	280 MB
Python runtime	15 MB	45 MB
Backend + MCP + web	1 MB	2 MB
Total	~180 MB	~450 MB
If you don't need the embedded browser, comment out the WebEngine hidden imports and set WEBENGINE_AVAILABLE = False in desktop/app.py. The bundle shrinks by ~120 MB.

Building
bash
pip install pyinstaller
pyinstaller pyinstaller.spec
The build takes 2–5 minutes. When it finishes:

bash
# Windows
dist\3olutionAgentGraph\3olutionAgentGraph.exe

# Linux / macOS
dist/3olutionAgentGraph/3olutionAgentGraph
Caveats
Platform	Caveat
Windows	UPX is disabled because it corrupts PyQt6 DLLs
macOS	The .app bundle is unsigned; Gatekeeper will block it until xattr -dr com.apple.quarantine is run
Linux	The bundle must be run on a machine with the same or newer glibc than the build machine
All	The backend must still be running somewhere reachable; the bundled desktop client talks to it over HTTP
macOS .app bundle
The spec includes a commented-out BUNDLE() block. Uncomment it when building on macOS to produce a double-clickable .app:

python
app = BUNDLE(
    coll,
    name="3olution Agent Graph.app",
    bundle_identifier="com.3olution.agentgraph",
     info_plist={ ... },
)
