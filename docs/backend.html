Complete source code and documentation bundle for the dynamic operating graph for AI agents. Multi-provider LLM routing (Ollama / fallback / llama-cpp), MCP tool integration, topological graph execution, SQLite persistence, PHP CGI execution, and a LiteGraph-based visual editor — all in one self-contained FastAPI backend.

Backend Overview

The backend is a FastAPI application that exposes three things over HTTP and WebSocket:

  1. A chat agent that streams tokens, reasons through tool calls, and persists conversations.
  2. A graph execution engine that runs user-built DAGs of LLM and tool nodes topologically.
  3. A management API for Ollama, llama-cpp, PHP, system state, and logs.

Five modules import nothing from the backend: config, state, retry, thinking, and storage. This means they can be tested in isolation, imported by scripts, and re-used by the desktop client without pulling in FastAPI or the openai SDK.

Startup sequence

main.py uses FastAPI's lifespan context manager. Every step is best-effort — nothing short of a Python import error prevents the app from starting.

  1. Logging — loguru console + rotating file sink.
  2. Environment checks — .env present? web files present? vendor files present?
  3. LLMClient — construct three AsyncOpenAI instances (lazy, no sockets opened).
  4. SessionStore — open the SQLite file and create tables.
  5. LlamaServerManager — spawn the llama-server subprocess if enabled and a model is available.
  6. MCPClient — spawn the MCP stdio server and initialize the session.
  7. Agent — instantiate with the LLM client, MCP client, and store.
  8. Warmup — send a one-token ping to the primary LLM to load weights early.
  9. Routers — mount the five routers.
  10. Static files — mount web/ at / last, so explicit HTML routes win.

Shutdown sequence

The lifespan's finally block runs in reverse:

  1. Close the MCP session (releases the stdio subprocess).
  2. Stop the llama-server (frees VRAM).
  3. The uvicorn loop exits.

Concurrency model

  • Async-first — every I/O operation is awaited. Nothing blocks the event loop.
  • sqlite3 via asyncio.to_thread — stdlib sqlite3 is synchronous, so every call is offloaded to a worker thread.
  • Subprocesses — llama-server, MCP, and PHP-CGI are subprocess.Popen instances. llama-server output is read on a background thread; MCP is fully async via stdio_client; PHP-CGI is a short-lived synchronous call inside to_thread.
  • Singletons — one LLMClient, one MCPClient, one SessionStore, one LlamaServerManager. All stored on state["..."].

Event stream

The generator yields dicts with a type field. The SSE route JSON-encodes each one; the WebSocket route sends it as a JSON frame; the JSON route collects them all into a list.

EventFieldsEmitted when
tokencontentA chunk of the final answer
thinkingcontentA chunk of reasoning (marker or reasoning_content)
retrymessageA transient LLM error is being retried
fallbackmessageSwitching to the secondary endpoint
infomessageNon-fatal notice (e.g. tools stripped)
tool_callname, argsThe agent is invoking an MCP tool
tool_resultname, resultThe tool returned
finalcontent, messagesTurn complete — always the last event
The final event is guaranteed. Every terminal path in Agent.run — normal completion, LLM error, max iterations, MCP exception — ends with exactly one final event. Clients can treat any event after final as a protocol violation.

System prompt injection

The system prompt is prepended to every turn from a module-level constant. It is never persisted: the stored history is messages[1:], so the system prompt is re-injected fresh on the next request. This means changing the prompt in code takes effect on the next turn, without migrating stored sessions.

Timeouts and cancellation

  • Per-request LLM timeout — AGENT_LLM_TIMEOUT (120 s default) applies to the initial connection.
  • Stream stall timeout — AGENT_STREAM_STALL_TIMEOUT (360 s) aborts a turn if no token arrives mid-stream.
  • Tool timeout — AGENT_TOOL_TIMEOUT (60 s) wraps each mcp.call_tool.
  • Client disconnect — when the SSE/WS client goes away, the generator is closed and the finally block in _consume_stream closes the upstream LLM stream.

LLM Provider Routing

LLMClient exposes one method surface (chat, chat_stream) and routes each call to one of three endpoints based on a provider string.

The three endpoints

Provider name(s)ClientDefault model
"auto", "primary", "ollama", "" self.primary AGENT_LLM_MODEL
"fallback" self.fallback AGENT_LLM_FALLBACK_MODEL
"llama_cpp", "llamacpp", "local" self.llama_cpp AGENT_LLAMA_CPP_ALIAS (default "local")

Provider resolution

def _resolve(self, provider: str) -> tuple[AsyncOpenAI, str]:
    p = (provider or "auto").lower()

    if p in ("llama_cpp", "llamacpp", "local"):
        return self.llama_cpp, settings.llama_cpp_alias or "local"

    if p == "fallback":
        if self.fallback is None:
            raise RuntimeError("Fallback LLM requested but ...")
        return self.fallback, settings.llm_fallback_model

    # "auto" / "primary" / "ollama" / ""
    return self.primary, settings.llm_model
Why the llama_cpp default model is an alias, not a path. The native llama-server binary is spawned with --alias <name> and advertises that alias as its model ID in /v1/models. Every chat request must send the same ID, or the server returns 404. The backend therefore sends settings.llama_cpp_alias — a stable short string like "local" — not the GGUF filename.

Automatic fallback

When the primary endpoint exhausts its retries, _run_llm_turn switches to the fallback endpoint — but only if three conditions hold:

  1. AGENT_LLM_FALLBACK_BASE_URL is set.
  2. The current provider is not llama_cpp (the local server is not a failover candidate).
  3. The primary failure was a retryable error (not a 400/auth error).

When the switch happens, a fallback event is yielded so the UI can render a "switching to fallback" notice, and the whole retry loop is repeated against self.fallback.

Tool stripping — four layers

The tools parameter is stripped from the outgoing request if any of these conditions is true:

LayerCheck
1. Requestdisable_tools=True on this call (per-request toggle)
2. GlobalAGENT_DISABLE_TOOLS=true in .env
3. User listModel name is in AGENT_NO_TOOLS_MODELS (comma-separated)
4. Runtime cacheModel previously returned "does not support tools" — added to _MODELS_WITHOUT_TOOLS

Layer 4 is automatic. The first time a model rejects tools with HTTP 400, the agent catches the BadRequestError, calls mark_model_without_tools(model), yields an info event, and retries without tools. Every subsequent request to that model skips the parameter from the start.

OpenAI-compatible surface

All three providers speak the OpenAI Chat Completions wire format. The client is a stock AsyncOpenAI — the only differences are the base URL, API key, and default model: 

AsyncOpenAI(
    base_url=settings.llm_base_url,          # e.g. http://localhost:11434/v1
    api_key=settings.llm_api_key or "ollama",
    timeout=settings.llm_timeout,
)

This means Ollama, llama.cpp, LM Studio, vLLM, Groq, Together, and the real OpenAI API are all first-class without any provider-specific code.

Agent Loop & Guard Rails

The agent is a linear perceive→decide→act loop. It runs up to AGENT_MAX_ITERATIONS (10 by default) turns, each of which is one streaming LLM call. After each turn, if the model emitted tool calls, the agent invokes them and loops again with the results appended.

The loop

for iteration in range(settings.max_iterations):
    turn_tools = tools if total_calls < MAX_TOOL_CALLS_PER_TURN else None

    content, tool_calls = await _run_llm_turn(messages, turn_tools, ...)

    messages.append(assistant message)

    if not tool_calls:
        yield final(content)      # done
        return

    for tc in tool_calls:
        result = await mcp.call_tool(tc.name, tc.args)
        messages.append(tool message)

Four independent guard rails

1. Duplicate tool-call suppression

Within a single turn, the agent tracks every (name, canonical_args_json) pair it has already executed. If the model asks for the exact same call twice, the second invocation is replaced with a canned message: 

"(skipped: NAME was already called with these exact
  arguments in this turn — produce a final answer now)"

The canned message is stored as the tool result, so the model sees it on the next turn and (usually) stops looping.

2. Tool-call cap

MAX_TOOL_CALLS_PER_TURN = 6. Once six distinct tool calls have executed, the agent stops passing tools to the LLM. The model is forced to answer with text on the next turn.

3. Stream stall timeout

Inside _consume_stream, the loop tracks last_event_at. If no delta arrives for AGENT_STREAM_STALL_TIMEOUT seconds (360 by default), the turn is aborted with a TimeoutError that names the timeout duration.

This catches the class of hang where a model accepts the connection, starts streaming, then goes silent mid-reasoning. Without this, the turn would block until the HTTP client's own timeout — which is often set to 0 (unlimited) for streaming.

4. Max iterations

If the outer loop exhausts AGENT_MAX_ITERATIONS without the model producing a text answer, the agent yields a final event with an explanatory message. This prevents an infinite ping-pong of tool calls.

The guards are independent. A model can hit each one in turn: 6 distinct tool calls (cap), then the same call twice (duplicate), then go silent (stall), then exceed iterations. Each one produces a coherent failure rather than hanging the request.

Reasoning token handling

Two sources of reasoning are handled:

  1. Marker-based — models that wrap reasoning in <thinking>…</thinking>, <think>…</think>, or prose markers. These are parsed incrementally by ThinkingSplitter (see thinking.py).
  2. Field-based — DeepSeek R1 and several OpenAI-compatible endpoints emit reasoning in a separate reasoning_content field on the streaming delta. The agent reads this via _extract_reasoning_content, which handles both the SDK's direct attribute and the model_extra dict.

Reasoning tokens are emitted as thinking events only. They are never added to state["content"], so they never leak into the persisted conversation.

Empty assistant content

When the model returns only tool calls and no text, the assistant message is stored with content: "" — an empty string, never null.

Two reasons:

  • OpenAI accepts null on assistant messages that carry tool_calls, but
  • llama-cpp-python's Pydantic validator rejects null and returns HTTP 500 with seven validation errors.

An empty string is accepted by every OpenAI-compatible server we have tested: OpenAI, Ollama, llama.cpp, vLLM, LM Studio, Groq, and Together.

Ollama unload-on-switch

When AGENT_OLLAMA_UNLOAD_ON_SWITCH=true (the default), switching models in the chat UI causes the agent to ask Ollama to unload the previously-used model. This frees VRAM before the new model loads.

The agent tracks self._last_ollama_model across requests. The unload is implemented as a POST /api/generate with keep_alive: 0, which is Ollama's documented way to force an unload.

llama-cpp pre-flight

When the request specifies provider="llama_cpp", the agent checks the local server's state before sending anything. Three checks are performed:

  1. Is the manager present on state["llama_server"]?
  2. Is the subprocess alive (mgr.is_running)?
  3. Does it answer /v1/models (mgr.is_ready())?

If any check fails, the agent yields a final event with a specific, actionable message and returns immediately, rather than retrying a doomed connection three times.

MCP Tool Integration

The backend talks to one Model Context Protocol server over stdio. The server is spawned as a subprocess using the same Python interpreter that runs the backend, so both processes share the same virtual environment and installed packages.

Default configuration

Bare interpreter resolution

If the user configures python, python3, py, or any of their .exe variants as the MCP command, the client rewrites it to sys.executable. This prevents the subprocess from picking up a system Python that lacks the mcp package.

Windows-specific handling

  • npx and similar Node tool shims are .ps1 or .cmd files that cannot be spawned directly. The client rewrites them to cmd /c npx ....
  • Closing an already-closed pipe raises ValueError on Windows. The close() method wraps exit_stack.aclose() in a suppress so the shutdown path never crashes on this.

MCP SDK 1.x / 2.x compatibility

The MCP Python SDK renamed one public attribute between major versions:

SDK versionAttribute name
1.xTool.inputSchema (camelCase)
2.xTool.input_schema (snake_case)

Pydantic v2 raises AttributeError on undeclared attributes, so accessing the wrong one crashes the backend the first time a tool-using turn runs. The _tool_input_schema() helper tries input_schema, then inputSchema, then falls back to a well-formed empty schema. The same code works against either SDK version without pinning.

Tool listing

list_tools_openai() calls session.list_tools() and converts each MCP tool to the OpenAI function-calling schema: 

{
  "type": "function",
  "function": {
    "name": t.name,
    "description": t.description or "",
    "parameters": _tool_input_schema(t),
  },
}

The resulting list is passed directly as the tools parameter on the outgoing chat request.

Tool invocation

call_tool(name, args) wraps session.call_tool in asyncio.wait_for with tool_timeout, and runs it through retry_async with a transport-level retry predicate: 

retry_on=(asyncio.TimeoutError, ConnectionError, OSError)

Business-level failures (an MCP tool returning {"isError": true}) are not retried — they are returned as a string so the LLM can see the error and adjust.

Content block extraction

MCP tool results are a list of content blocks. Each block has a .text attribute (for text blocks) or is stringified for other block types (images, resource links). All blocks are joined with newlines: 

parts = []
for block in result.content:
    text = getattr(block, "text", None)
    parts.append(text if text is not None else str(block))
return "\n".join(parts) if parts else "(empty result)"

Failure modes

SymptomCause

Graph Execution Engine

The graph engine runs user-built DAGs of nodes. Each node is a Python async function with a fixed signature: 

async def node_fn(ctx, inputs, params) -> dict:
  • ctx — an ExecutionContext with .app (the shared state dict) and .outputs (results of upstream nodes).
  • inputs — values from connected upstream nodes, keyed by input port name.
  • params — widget values configured on the node itself.

The return value is a dict keyed by output port name.

Topological execution

Nodes are ordered by Kahn's algorithm. The graph must be a DAG — cycles are rejected with an error event that recommends control.foreach for iteration. 

order = _topo_sort(graph)   # [node_id, ...] or ValueError

for node_id in order:
    result = await nt.fn(ctx, inputs, params)
    ctx.outputs[node_id] = result

The llm.chat node and dynamic params

llm.chat exposes a model widget whose options are populated at runtime from /api/llama/all-models. This endpoint returns both Ollama models and local GGUF files, each tagged with a provider: 

{ "id": "ollama::llama3.2",              "provider": "ollama",    ... }
{ "id": "llama_cpp::Bonsai-8B.gguf",    "provider": "llama_cpp", ... }

The frontend encodes each option as provider::model. When the graph runs, _decode_model_and_provider() splits the string and picks the right provider for that one call. A single graph can therefore mix Ollama and llama-cpp nodes.

Custom nodes

Any .py file in backend/graph/custom_nodes/ is auto-loaded on startup. Files starting with an underscore are skipped (private helpers). Broken modules log a full traceback at ERROR level but do not prevent the other nodes from loading.

Set AGENT_LOAD_CUSTOM_NODES=false to disable the loader entirely — the escape hatch when a bad custom node is blocking startup.

Persistence

Every run is saved to graph_runs with:

  • The original payload (nodes + edges).
  • The full event stream as a JSON array.
  • Status (ok / error).
  • Final text extracted from the first output.text node.
  • Node and event counts.
  • ISO 8601 timestamp.

Rows are pruned automatically beyond AGENT_MAX_GRAPH_RUNS (default 100).

Route ordering contract

Starlette matches routes in registration order. Two literal paths must be registered before the {run_id} catch-all:

  1. /api/graph/runs/latest
  2. /api/graph/runs/all

Otherwise latest and all are captured as run IDs and the endpoints become unreachable.

Concurrency — one connection per call

Every public method opens a fresh sqlite3.Connection, executes, and closes. No connection pool. This is slightly less efficient than a shared connection, but it sidesteps every "database is locked" scenario and works correctly across asyncio.to_thread() boundaries (a sqlite3.Connection cannot be shared between threads). 

async def save(self, session_id, history):
    def _save():
        conn = sqlite3.connect(self.db_path)
        try:
            # ...
            conn.commit()
        finally:
            conn.close()
    await asyncio.to_thread(_save)

Retention

  • Sessions — never pruned automatically. Delete via DELETE /api/sessions/{id}.
  • Graph runs — pruned to the newest AGENT_MAX_GRAPH_RUNS (default 100) after every save. Set higher for a longer history, lower to keep the file small.

Session save points

The agent saves the session on every terminal path:

Terminal conditionSaved?
Normal completionYes
LLM error (turn_failed)Yes
Max iterations reachedYes
Client disconnect mid-turnNo (generator closed)
Process killed (SIGKILL)No
The system prompt is never stored. Session histories are persisted as messages[1:] — the leading system message is stripped before the save. It is re-injected on the next request. This keeps the stored history focused on user-visible conversation and makes prompt changes take effect immediately.

WebSocket Protocols

Two WebSocket endpoints exist. Both are bidirectional — the client sends a request frame, the server streams events back. The connection stays open and can serve multiple requests sequentially.

/ws — chat

Client → server

{
  "message": "string",
  "history": [ ... ],
  "model": "string | null",
  "provider": "auto",
  "session_id": "string | null",

Server → client

One frame per event, with the same schema as the SSE /api/chat/stream endpoint: 

{"type": "token",       "content": "..."}
{"type": "thinking",    "content": "..."}
{"type": "tool_call",   "name": "...", "args": "..."}
{"type": "tool_result", "name": "...", "result": "..."}
{"type": "final",       "content": "...", "messages": [ ... ]}

Closing

The connection stays open until the client closes it or the server errors. A final event always arrives before the next turn begins.

/ws/graph — graph execution

Client → server

{
  "id": "default",
  "name": "My Graph",
  "nodes": [ { "id": "n1", "type": "input.text", "params": {...} }, ... ],
  "edges": [ { "id": "e1", "from_node": "n1", "from_output": "text",
               "to_node": "n2", "to_input": "messages" }, ... ]
}

Server → client

{"type": "graph_start", "order": ["n1", "n2", "n3"]}
{"type": "node_start",  "node": "n1"}
{"type": "node_done",   "node": "n1", "outputs": {"text": "..."}}
{"type": "node_error",  "node": "n2", "error": "..."}
{"type": "graph_done",  "outputs": { ... }}
{"type": "run_saved",   "run_id": "..."}

Multiple runs per connection

The graph WebSocket loops: after each graph completes (and is persisted), the server waits for the next payload. This makes it suitable for a live editor where the user iterates on a graph and clicks Run repeatedly.

JSON serialisation

The /api/chat/stream SSE route uses json.dumps(ev, default=str), so any non-serialisable value is stringified rather than raising. This is what lets tool results that contain arbitrary Python objects pass through cleanly.

Error handling

FailureBehaviour
Agent not initialised Server sends a final event with an explanatory message, then closes the connection.
Client disconnects mid-turn WebSocketDisconnect is caught. The generator is closed. The session is not saved.
Unexpected exception in the handler Logged at ERROR level, then a final event with the exception message is sent before closing.

Reconnect strategy

Neither endpoint implements resume. A dropped connection loses the current turn. Clients should:

  1. Detect the close.
  2. Reconnect (optionally with exponential backoff).
  3. Reload the session history from /api/sessions/{id} to recover state.

Errors & Retries

Every LLM call and MCP tool call funnels through retry_async, which takes a should_retry predicate or a retry_on tuple of exception types.

Retry helper

async def retry_async(
    fn,
    attempts: int = 3,
    backoff: float = 1.0,
    retry_on: tuple[type[BaseException], ...] = (Exception,),
    should_retry: ShouldRetryFn | None = None,
    label: str = "operation",
) -> T:

The wait before attempt N is backoff * 2**(N-1):

AttemptWait before (with backoff=1.0)
1st— (immediate)
2nd1.0 s
3rd2.0 s
4th4.0 s

Two control-flow exceptions are never swallowed: KeyboardInterrupt, SystemExit, and asyncio.CancelledError propagate immediately.

LLM error classification

llm.is_retryable(exc) decides whether an LLM exception is worth retrying:

ExceptionRetried?Reason
openai.APIConnectionError✅Transient network blip
openai.APITimeoutError✅Transient slowness
openai.RateLimitError✅Backoff usually helps
openai.InternalServerError (5xx)✅ ** Unless the body matches a permanent marker
openai.BadRequestError (400)❌The request itself is wrong
openai.AuthenticationError (401)❌Retrying will not fix a bad key
openai.PermissionDeniedError (403)❌Retrying will not fix a forbidden request
openai.NotFoundError (404)❌Model does not exist

Permanent 5xx markers

A 5xx response is not retried if its body contains any of the following substrings: 

"unknown pre-tokenizer"
"error loading model"
"llama-server process has terminated"
"failed to load model"
"does not support tools"
"model not found"

These indicate a permanent condition for this request. Retrying just wastes three waits of 1s, 2s, 4s and floods the logs.

Tool error handling

MCP tool calls use a different predicate — a transport-level exception tuple: 

retry_on=(asyncio.TimeoutError, ConnectionError, OSError)

Anything else is treated as a business-level error and returned to the model as a string, so it can react rather than have the whole turn fail.

Agent-level retries

The agent loop has its own retry logic in _run_llm_turn, layered on top of the retry helper:

  1. Try the primary provider up to AGENT_RETRY_ATTEMPTS times.
  2. Yield a retry event before each wait.
  3. On exhaustion, if a fallback is configured, yield a fallback event and repeat against the fallback.
  4. If both fail, yield a turn_failed sentinel with a combined error message.

The "does not support tools" special case

A 400 with the message "does not support tools" (or variants) is not treated as a fatal error. It is caught, the model is added to the runtime cache, an info event is emitted, and the turn is retried without the tools parameter.

Detected phrasings: 

"does not support tools"
"tools are not supported"
"tool" + "not supported"

Streaming retry boundary

For streaming calls, only the initial open of the stream is retried. Once bytes start flowing, mid-stream errors propagate up to _consume_stream, which can trigger the stall timeout. There is no mid-stream reconnect — the whole turn is re-attempted at the outer loop.

PHP execution errors

execute_php never raises. It returns a structured dict with a status code and an error key (php_not_found, script_not_found, timeout, no_cgi_headers). The route translates that into an HTTP response.

Access log filtering

Both the backend's loguru config and the desktop client filter uvicorn access log lines whose status code is 2xx or 3xx. The frontend polls /api/health every 10 s, /api/ollama/ps every 5 s, and /api/graph/runs on page load. Without filtering, a 4-hour session produces thousands of identical INFO: 127.0.0.1:xxxxx - "GET /api/health HTTP/1.1" 200 OK lines.

4xx and 5xx lines are not filtered — those represent real problems.

Stop-all endpoint

POST /api/system/stop-all is a coordinated shutdown. It returns immediately with {"status": "stopping"} and then runs the actual shutdown in a background task:

  1. Wait 0.8 s (so the HTTP response reaches the client).
  2. Stop llama-cpp (taskkill /F /T on Windows, SIGTERM on Unix).
  3. Close the MCP session.
  4. Terminate the backend process itself (os._exit(0) on Windows, SIGTERM on Unix).

Diagnostics checklist

When something is wrong, check these in order:

  1. GET /api/health — which subsystem is not green?
  2. GET /api/logs/recent?lines=500 — what did the last 500 lines say?
  3. The llama_cpp and mcp_connected fields — are the subprocesses up?
  4. GET /api/system/status — full subsystem state including PID.

"""
Async retry helper with exponential backoff.
https://3olution.com

Callers can specify which exceptions to retry in one of two ways:

    retry_on=(ValueError, KeyError, ...)
        A tuple of exception classes. Any exception that is an
        instance of one of these is retried. This is the simple form
        used by backend/mcp_client.py for its transport-level retries.

    should_retry=callable
        A predicate that takes the caught exception and returns True
        if the operation should be retried. This is the flexible form
        used by backend/llm.py, where whether to retry depends on the
        HTTP status code and the error message.

If both are supplied, `should_retry` wins. If neither is supplied,
every exception is retried up to `attempts` times.

================================================================
  LOGGING
================================================================

  Each failed attempt logs at WARNING level with the attempt number
  and the wait time. The final failure logs at ERROR level. The
  `label` argument lets the caller identify the operation in logs —
  for example "LLM auto stream (model=llama3.2)".
"""

from __future__ import annotations

import asyncio
from typing import Awaitable, Callable, Optional, TypeVar

from loguru import logger

T = TypeVar("T")

# A predicate that takes an exception and returns True if the
# operation should be retried.
ShouldRetryFn = Callable[[BaseException], bool]


async def retry_async(
    fn: Callable[[], Awaitable[T]],
    attempts: int = 3,
    backoff: float = 1.0,
    retry_on: tuple[type[BaseException], ...] = (Exception,),
    should_retry: Optional[ShouldRetryFn] = None,
    label: str = "operation",
) -> T:
    """
    Call `fn()` up to `attempts` times with exponential backoff.

    Parameters
    ----------
    fn
        A zero-argument coroutine function. Each call produces a
        fresh awaitable.
    attempts
        Maximum number of attempts. Clamped to at least 1.
    backoff
        Base delay in seconds. The wait before attempt N is
        `backoff * 2**(N-1)`.
    retry_on
        Tuple of exception classes. Only used when `should_retry`
        is None.
    should_retry
        Optional predicate. When supplied, replaces `retry_on`. The
        predicate receives the caught exception and returns True if
        the operation should be retried.
    label
        Human-readable name for logs.

    Returns
    -------
    The value returned by `fn()` on success.

    Raises
    ------
    The last exception raised by `fn()` if every attempt fails, or
    the first non-retryable exception if `should_retry` returns False.
    """
    attempts = max(1, attempts)
    last_exc: Optional[BaseException] = None

    # Resolve the retry decision function once, before the loop.
    # Two paths:
    #
    #   1. should_retry is provided → use it directly.
    #   2. otherwise → build a closure over `retry_on` that does an
    #      isinstance check.
    #
    # Building a single callable lets the loop body call
    # `decide(exc)` without branching on every iteration.
    if should_retry is not None:
        decide: ShouldRetryFn = should_retry
    else:
        def decide(exc: BaseException) -> bool:
            return isinstance(exc, retry_on)

    for i in range(attempts):
        try:
            return await fn()
        except BaseException as exc:  # noqa: BLE001 — intentionally broad
            # Never swallow CancelledError or KeyboardInterrupt —
            # those are control flow, not operational failures.
            if isinstance(exc, (KeyboardInterrupt, SystemExit)):
                raise
            if isinstance(exc, asyncio.CancelledError):
                raise

            last_exc = exc

            # Ask the predicate whether this exception is retryable.
            try:
                retryable = bool(decide(exc))
            except Exception:
                # A misbehaving predicate should not mask the real
                # error. Treat it as "do not retry".
                retryable = False

            if not retryable:
                logger.debug(
                    "{} raised non-retryable {}: {}",
                    label, type(exc).__name__, exc,
                )
                raise

            if i < attempts - 1:
                wait = backoff * (2 ** i)
                logger.warning(
                    "{} failed (attempt {}/{}): {}. Retrying in {:.1f}s...",
                    label, i + 1, attempts, exc, wait,
                )
                await asyncio.sleep(wait)
            else:
                logger.error(
                    "{} failed after {} attempts: {}",
                    label, attempts, exc,
                )

    assert last_exc is not None
    raise last_exc

"""
Streaming parser for reasoning blocks.
https://3olution.com

Some language models emit their chain-of-thought wrapped in special
markers before the final answer. This module splits a token stream
into two lanes — thinking and text — so the UI can render them
separately.

================================================================
  SUPPORTED MARKERS
================================================================

  Long markers are matched first, so a stream that contains
  "" is not mis-detected as "" + "king".

      ...       (Anthropic-style)
      ...             (DeepSeek R1, Qwen 3)
      \n...               (some QwQ variants)
      <|thinking|> ...               (rare, some finetunes)
      Thinking: ...                  (fallback)

  In addition, DeepSeek R1 and several OpenAI-compatible reasoning
  endpoints emit their reasoning in a SEPARATE field of the streaming
  delta object, `reasoning_content`, rather than inside `content`.
  The agent loop handles that case directly — this module only
  handles markers embedded in the content stream.

================================================================
  INCREMENTAL PARSING
================================================================

  The splitter is incremental. It accepts arbitrary chunks of text
  and emits (kind, content) tuples, where kind is "text" or
  "thinking". It buffers a few characters at the tail so a marker
  split across two chunks is still recognised.

  Example: if a chunk ends with "", the splitter does not emit "", ""),

    # DeepSeek R1 / Qwen 3 / Granite
    ("", ""),
    ("\n", ""),

    # QwQ variants (leading newline)
    ("\n", ""),

    # Rare prose-style markers
    ("<|thinking|>", "\n\n"),
    ("Thinking:", "\n\n"),
]


# ══════════════════════════════════════════════════════════════════════
#  ThinkingSplitter
# ══════════════════════════════════════════════════════════════════════

class ThinkingSplitter:
    """
    Incremental splitter for reasoning blocks in a token stream.

    The `enabled` flag controls whether the splitter does any work at
    all. When False, every chunk is emitted as text with no parsing —
    the fast path when the user has turned reasoning off.
    """

    def __init__(self, enabled: bool = True) -> None:
        self.enabled = enabled
        self.pending = ""
        self.inside = False
        # The specific close marker for the currently-open block.
        self._open = ""
        self._close = ""

    # ── Internal helpers ──────────────────────────────────────────────

    def _max_open_len(self) -> int:
        """Length of the longest opening marker, minus one."""
        return max(len(m) for m, _ in _MARKER_PAIRS) - 1

    def _max_close_len(self) -> int:
        """Length of the longest closing marker, minus one."""
        return max(len(m) for _, m in _MARKER_PAIRS) - 1

    def _find_opening(self) -> tuple[int, str, str] | None:
        """
        Find the earliest opening marker in self.pending.

        Returns (index, open_marker, close_marker) or None if no
        marker is present.
        """
        best: tuple[int, str, str] | None = None
        for open_m, close_m in _MARKER_PAIRS:
            idx = self.pending.find(open_m)
            if idx == -1:
                continue
            if best is None or idx < best[0]:
                best = (idx, open_m, close_m)
        return best

    # ── Public API ────────────────────────────────────────────────────

    def feed(self, text: str) -> list[tuple[str, str]]:
        """
        Feed a chunk of text.

        Returns a list of (kind, content) tuples. kind is "text" or
        "thinking". May return an empty list if the chunk is entirely
        buffered awaiting more input.
        """
        if not text:
            return []

        if not self.enabled:
            return [("text", text)]

        self.pending += text
        results: list[tuple[str, str]] = []

        while True:
            if not self.inside:
                # ── Looking for an opening marker ────────────────────
                found = self._find_opening()
                if found is None:
                    # No opening marker in the buffer. Emit everything
                    # except the last few characters, in case a marker
                    # straddles the chunk boundary.
                    keep = self._max_open_len()
                    if len(self.pending) > keep:
                        emit = self.pending[:-keep]
                        self.pending = self.pending[-keep:]
                        if emit:
                            results.append(("text", emit))
                    break

                idx, open_m, close_m = found
                if idx > 0:
                    results.append(("text", self.pending[:idx]))
                self.pending = self.pending[idx + len(open_m):]
                self._open = open_m
                self._close = close_m
                self.inside = True
            else:
                # ── Looking for the matching closing marker ──────────
                if self._close:
                    idx = self.pending.find(self._close)
                else:
                    # Empty close marker: block ends at a blank line
                    # or at end-of-stream.
                    idx = self.pending.find("\n\n")
                    if idx == -1:
                        # No blank line yet — emit everything except
                        # the last character to catch a "\n" split
                        # across chunks.
                        keep = 1
                        if len(self.pending) > keep:
                            emit = self.pending[:-keep]
                            self.pending = self.pending[-keep:]
                            if emit:
                                results.append(("thinking", emit))
                        break

                if idx == -1:
                    # No closing marker yet. Buffer the tail so a
                    # split closing marker is still matched.
                    keep = self._max_close_len() if self._close else 1
                    if len(self.pending) > keep:
                        emit = self.pending[:-keep]
                        self.pending = self.pending[-keep:]
                        if emit:
                            results.append(("thinking", emit))
                    break

                if idx > 0:
                    results.append(("thinking", self.pending[:idx]))
                self.pending = self.pending[idx + len(self._close):]
                self.inside = False

        return results

    def flush(self) -> list[tuple[str, str]]:
        """
        Flush any remaining buffered content.

        Call this at end-of-stream. Any text still in the buffer is
        emitted as either "thinking" (if we never saw a closing
        marker) or "text".
        """
        if not self.pending:
            return []

        kind = "thinking" if self.inside else "text"
        content = self.pending
        self.pending = ""
        return [(kind, content)]

#  Convenience function for finished strings
# ══════════════════════════════════════════════════════════════════════

"""
SQLite-backed persistence layer.
https://3olution.com

Two tables are managed:

    sessions     — chat conversation history, one row per session_id
    graph_runs   — graph execution history, one row per run

Uses the stdlib sqlite3 module via asyncio.to_thread() so no extra
dependency is required. The database file is created on first use.

================================================================
  WHY ONE CONNECTION PER CALL
================================================================

  Every public method opens a fresh sqlite3 connection, executes,
  and closes. This is the "no connection pool" pattern — it is
  slightly less efficient than keeping one connection alive, but it
  sidesteps every "database is locked" scenario and works correctly
  across asyncio.to_thread() boundaries (a sqlite3.Connection cannot
  be used from multiple threads).

  SQLite's single-writer semantics are respected automatically.

================================================================

    id              — UUID assigned at save time

    status          — "ok" | "error"

"""
Logging setup for the backend using loguru.
https://3olution.com

Two sinks are configured:

  Console (stderr) — level AGENT_LOG_LEVEL (default INFO)
  File (rotating)  — level AGENT_LOG_FILE_LEVEL (default DEBUG)

The console sink is meant for a human operator watching the terminal.
The file sink captures everything at DEBUG level so that a bug report
can be diagnosed after the fact without re-enabling verbose logging.

================================================================
  ROTATION AND RETENTION
================================================================
#
  Log files rotate at midnight UTC and are named:

      logs/backend-YYYY-MM-DD.log

  Retention is AGENT_LOG_RETENTION_DAYS (default 14). Files older
  than that are deleted automatically.

================================================================
  FILE HANDLING ON WINDOWS
================================================================
#
  The file sink uses `enqueue=True`, which routes every log call
  through a background thread. This makes logging safe to call from
  asyncio without blocking the event loop, and it also avoids the
  classic Windows issue where an antivirus scanner holds the file
  open while Python tries to rotate it.

  If the process is killed with SIGKILL (or Ctrl+Break on Windows),
  some log lines still in the queue may be lost. This is acceptable:
  the alternative — synchronous file writes on every log line — is
  a significant performance cost on the hot path.

import sys

from loguru import logger

from .config import settings

    removes the default handler, subsequent calls are no-ops because
    `logger.remove()` clears everything.

    logger.remove()

    # ── Console sink ─────────────────────────────────────────────────
    console_format = (
        "{time:YYYY-MM-DD HH:mm:ss} | "
        "{level: <8} | "
        "{name}:{line} — "

"""
Multi-provider LLM client.
https://3olution.com

Routes requests to one of three OpenAI-compatible endpoints:

    primary   -- the main endpoint (default: Ollama)
    fallback  -- an optional secondary endpoint, tried only after the
                 primary has exhausted its retries
    llama_cpp -- the locally-managed llama-server subprocess
                 (either the native llama-server.exe binary or the
                 Python llama_cpp.server module)

================================================================
  DESIGN NOTES
================================================================

  All three endpoints speak the OpenAI Chat Completions wire format,
  so a single `AsyncOpenAI` class serves all of them. The only thing
  that differs between them is the base URL, API key, default model,
  and (for llama-cpp) whether the server is currently running.

  The agent loop selects a provider per turn. The `provider` string
  is resolved by `_resolve()` into a (client, default_model) pair.
  Aliases ("local", "llamacpp") map to the canonical name so callers
  are free to spell it however the frontend happens to.

================================================================
  THE disable_tools PARAMETER
================================================================

  Both `chat()` and `chat_stream()` accept a `disable_tools` flag.
  When true, the `tools` parameter is stripped from the outgoing
  request regardless of what the caller passed in.

  This is a second layer of defence on top of `should_use_tools()`:
  the agent loop already computes `allow_tools` from the model name
  and the global config, but passing `disable_tools` through to the
  client guarantees that a stray tool schema never reaches a model
  that will reject it, even if a future caller forgets the check.

================================================================
  ERROR CLASSIFICATION
================================================================

  Not all exceptions are worth retrying. The retry helper in
  backend/retry.py accepts a `should_retry(exc) -> bool` predicate,
  and this module provides `is_retryable(exc)`:

    Retryable:
      - Any connection error (network blip, DNS, timeout)
      - HTTP 5xx, EXCEPT those whose body clearly indicates a
        permanent condition (missing model, unsupported template)

    Not retryable:
      - HTTP 400 (bad request -- the request itself is wrong)
      - HTTP 401 / 403 (auth -- retrying won't help)
      - HTTP 404 (model not found -- retrying won't help)
      - HTTP 5xx whose message matches a permanent-error marker

  The marker list is deliberately conservative. Retrying a permanent
  error costs three waits of 1s, 2s, 4s for nothing.

================================================================
  TOOL-SUPPORT CACHE
================================================================

  Some models reject the `tools` parameter outright with HTTP 400
  "model does not support tools". Retrying won't fix it -- the model
  simply cannot function-call.

  Rather than let that error reach the user, we cache the model name
  in a module-level set the first time it fails, and strip `tools`
  from every subsequent request to that model. The user sees a
  one-time info event ("this model does not support tools") and then
  the conversation continues normally.

  The cache is in-memory and per-process. It is reset on restart,
  which is fine -- the first request after a restart re-learns it.

  Users can pre-populate the cache via AGENT_NO_TOOLS_MODELS, which
  is useful when they already know a model's limitations.

================================================================
  THE llama_cpp PROVIDER AND THE ALIAS
================================================================

  The native llama-server.exe binary is spawned with
  `--alias `. The server advertises that
  alias as the model ID in /v1/models. Every chat and embedding
  request must send the same ID, or the server returns 404.

  `_resolve()` therefore returns `settings.llama_cpp_alias`
  (default "local") as the default_model for the llama_cpp
  provider. It does NOT resolve a file path, because the server
  has already been told what file to load and only knows the alias.

  This is the same strategy used for the primary and fallback
  endpoints: the client sends a stable ID, not an implementation
  detail like a file path.
"""

_PERMANENT_500_MARKERS = (
    "unknown pre-tokenizer",
    "error loading model",
    "llama-server process has terminated",
    "failed to load model",
    "does not support tools",
    "model not found",

def is_retryable(exc: BaseException) -> bool:
    """
    Return True if the given exception is worth retrying.

    Used by backend/retry.py's `should_retry` predicate.
    """
    # 4xx responses are almost always permanent -- auth, bad request,
    # missing model. Retrying costs time and logs noise.
    if isinstance(exc, openai.BadRequestError):
        return False
    if isinstance(exc, openai.AuthenticationError):
        return False
    if isinstance(exc, openai.PermissionDeniedError):
        return False
    if isinstance(exc, openai.NotFoundError):
        return False

    # 5xx: check the message for known-permanent markers.
    if isinstance(exc, openai.InternalServerError):
        text = str(exc).lower()
        for marker in _PERMANENT_500_MARKERS:
            if marker in text:
                return False
        return True

    # Everything else (connection errors, timeouts, rate limits) is
    # worth a retry.
    return True


def is_no_tools_error(exc: BaseException) -> bool:
    """
    Return True if the exception indicates the model rejects the
    `tools` parameter.

    Different providers phrase this differently:

        OpenAI:   "model does not support tools"
        Groq:     "tools are not supported by this model"
        Together: "invalid_request_error: tools not supported"

    We match any message containing both "tool" and a negation.
    """
    if not isinstance(exc, openai.BadRequestError):
        return False
    msg = str(exc).lower()
    return (
        "does not support tools" in msg
        or "tools are not supported" in msg
        or ("tool" in msg and "not supported" in msg)
    )

def should_use_tools(model: str, request_disable: bool = False) -> bool:
    """
    Return True if tools should be sent to the given model.

    Checks four conditions in order:

      1. The caller explicitly disabled tools for this request
         (the "No tools" toggle in the chat UI).
      2. AGENT_DISABLE_TOOLS is true (global kill switch).
      3. The model is in AGENT_NO_TOOLS_MODELS (user-configured).
      4. The model has previously returned a "does not support tools"
         error (auto-cached during this process lifetime).
    """
    if request_disable:
        return False
    if settings.disable_tools:
        return False
    if model and model in settings.no_tools_model_list:
        return False
    if model and model in _MODELS_WITHOUT_TOOLS:
        return False
    return True

    provider-routed interface.

    The three AsyncOpenAI instances are created at construction time.
    They do not open any sockets -- the SDK is lazy. Connections are
    established on the first request to each endpoint.
    """

    def __init__(self) -> None:
        # -- Primary endpoint -----------------------------------------
        self.primary = AsyncOpenAI(

            api_key=settings.llm_api_key or "ollama",
            timeout=settings.llm_timeout,

        # -- Fallback endpoint (optional) -----------------------------
        self.fallback: AsyncOpenAI | None = None

        # This client always exists. Whether the server is actually
        # running is checked by the agent's pre-flight before routing

        # with a connection error rather than hanging.

        Raises RuntimeError if the requested provider is not

            # so it advertises a short stable ID in /v1/models. The

            # server returns 404 (or hangs) on every call.

            # string in .env (AGENT_LLAMA_CPP_ALIAS, default "local").

            # Python llama_cpp.server module -- that module is also
            # started with --model_alias, so both backends behave
            # identically here.

                "llama_cpp provider resolved: default_model='{}' (alias)",
                default_model,

                    "is not set."

"""
MCP client — Windows-safe stdio connection to an MCP server subprocess.
https://3olution.com

Key fixes:

  - Bare interpreter names ("python", "python3", "py") are resolved
    to sys.executable, so the subprocess always uses the SAME venv.

  - The connection is retried once, handling transient spawn races.

  - Cleanup suppresses ValueError on Windows closed pipes.

  - The `Tool.inputSchema` attribute (MCP SDK 1.x) was renamed to
    `Tool.input_schema` in SDK 2.x. The `_tool_input_schema()`
    helper reads whichever one is present, so the same code works
    against either version of the SDK.

================================================================
  WHY THE SDK VERSION CHECK MATTERS
================================================================

  The MCP Python SDK changed one public attribute between major
  versions:

      SDK 1.x:   Tool.inputSchema   (camelCase)
      SDK 2.x:   Tool.input_schema  (snake_case)

  Pydantic v2 raises AttributeError when an undeclared attribute is
  accessed, so `tool.inputSchema` on a v2 Tool object crashes the
  backend the first time a tool-using turn runs.

  Rather than pin the SDK version, we accept both. The helper tries
  `input_schema` first, then falls back to `inputSchema`, then to a
  well-formed empty schema. That way the same code works against
  any currently-installed SDK.
"""

from __future__ import annotations

from typing import Any

#  Bare interpreter resolution

_BARE_INTERPRETERS = {

    "python.exe", "python3.exe", "py.exe",
    "python3.10", "python3.11", "python3.12", "python3.13",

    "python3.12.exe", "python3.13.exe",
}


def _resolve_command(command: str) -> str:
    """Replace bare interpreter names with sys.executable."""
    if command.lower() in _BARE_INTERPRETERS and sys.executable:
        return sys.executable
    return command


# ══════════════════════════════════════════════════════════════════════
#  Tool schema compatibility helper
# ══════════════════════════════════════════════════════════════════════

def _tool_input_schema(tool: Any) -> dict:
    """
    Return a tool's JSON input schema, whatever the SDK calls it.

    Reads `input_schema` (MCP SDK 2.x) first, then `inputSchema`
    (MCP SDK 1.x). Falls back to a well-formed empty object schema
    if neither is present, which prevents a missing schema from
    crashing the whole tool list.
    """
    # SDK 2.x name.
    schema = getattr(tool, "input_schema", None)

    # SDK 1.x name.
    if schema is None:
        schema = getattr(tool, "inputSchema", None)

    # Neither present — return a minimal valid schema.
    if schema is None:
        return {"type": "object", "properties": {}}

    # A JSON schema is a dict. Some SDK versions wrap it in a
    # pydantic model with a `.model_dump()` method.
    if isinstance(schema, dict):
        return schema

    dump = getattr(schema, "model_dump", None)
    if callable(dump):
        try:
            return dump(exclude_none=True)
        except Exception:
            pass

    # Last resort: stringify. The LLM will at least see something.
    return {"type": "object", "properties": {}, "x-raw": str(schema)}

class MCPClient:
    """Manages a persistent stdio connection to one MCP server."""

    def __init__(self) -> None:
        self.session: ClientSession | None = None
        self.exit_stack = AsyncExitStack()
        self._connected = False
        self._effective_command: str = ""
        self._effective_args: list[str] = []

    # ══════════════════════════════════════════════════════════════════
    #  Connect
    # ══════════════════════════════════════════════════════════════════

    async def connect(
        self,
        command: str,
        args: list[str],
        retries: int = 1,
    ) -> None:
        """Spawn the MCP server and initialise the session."""
        original_command = command
        command = _resolve_command(command)
        if command != original_command:
            logger.info(
                "Resolved MCP command '{}' -> '{}'",
                original_command, command,
            )

        # Windows: npx and similar node tools are .ps1/.cmd shims
        # that cannot be spawned directly. Wrap in cmd /c.
        if sys.platform == "win32" and command.lower() in ("npx", "npx.ps1"):
            logger.info("Windows detected - wrapping '{}' in cmd /c", command)
            args = ["/c", command, *args]
            command = "cmd"

        # If the user gave an absolute path, verify it exists.
        cmd_path = Path(command)
        if cmd_path.is_absolute() and not cmd_path.exists():
            raise FileNotFoundError(
                f"MCP server command does not exist: {command}"
            )

        self._effective_command = command
        self._effective_args = list(args)

        logger.info("Spawning MCP server: {} {}", command, " ".join(args))

        last_exc: Exception | None = None
        for attempt in range(retries + 1):
            params = StdioServerParameters(command=command, args=args)
            try:
                self.exit_stack = AsyncExitStack()
                read, write = await self.exit_stack.enter_async_context(
                    stdio_client(params)
                )
                self.session = await self.exit_stack.enter_async_context(
                    ClientSession(read, write)
                )
                await self.session.initialize()
                self._connected = True
                logger.info("MCP session initialised")
                return
            except Exception as exc:
                last_exc = exc
                logger.warning(
                    "MCP connect attempt {}/{} failed: {}",
                    attempt + 1, retries + 1, exc,
                )
                with suppress(Exception):
                    await self.exit_stack.aclose()
                self.exit_stack = AsyncExitStack()
                self.session = None
                self._connected = False
                if attempt < retries:
                    await asyncio.sleep(0.5)

        assert last_exc is not None
        hint_cmd = f"{self._effective_command} {' '.join(self._effective_args)}"
        logger.error(
            "MCP connection failed after {} attempt(s).\n"
            "  Interpreter: {}\n"
            "  Command:     {}\n"
            "  Hint: run this to see the real error:\n"
            "      {}",
            retries + 1, sys.executable, hint_cmd, hint_cmd,
        )
        raise last_exc

    # ══════════════════════════════════════════════════════════════════
    #  Close
    # ══════════════════════════════════════════════════════════════════

    async def close(self) -> None:
        """Gracefully close the MCP session."""
        if not self._connected:
            return
        # Windows raises ValueError when closing an already-closed
        # pipe. Suppressing it here is intentional.
        with suppress(ValueError, Exception):
            await self.exit_stack.aclose()
        self._connected = False
        logger.info("MCP session closed")

    # ══════════════════════════════════════════════════════════════════
    #  Tools
    # ══════════════════════════════════════════════════════════════════

    async def list_tools_openai(self) -> list[dict]:
        """
        Return all MCP tools in OpenAI function-calling schema.

        Reads the input schema via `_tool_input_schema()`, which
        works with both MCP SDK 1.x (`inputSchema`) and 2.x
        (`input_schema`).
        """
        if self.session is None:
            return []

        try:
            result = await self.session.list_tools()
        except Exception as exc:
            logger.error("Failed to list MCP tools: {}", exc)
            return []

        tools: list[dict] = []
        for t in result.tools:
            tools.append({
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description or "",
                    "parameters": _tool_input_schema(t),
                },
            })
        return tools

    async def call_tool(self, name: str, args: dict) -> str:
        """
        Invoke an MCP tool and return its output as a string.

        Transport-level failures (timeout, connection reset, OS
        error) are retried up to `AGENT_RETRY_ATTEMPTS` times with
        exponential backoff. Business-level failures are returned as
        a string so the LLM can see the error and react.
        """
        if self.session is None:
            return "Error: MCP session not connected."

        async def _do_call() -> str:
            result = await asyncio.wait_for(
                self.session.call_tool(name, args),
                timeout=settings.tool_timeout,
            )
            parts: list[str] = []
            for block in result.content:
                text = getattr(block, "text", None)
                if text is not None:
                    parts.append(text)
                else:
                    parts.append(str(block))
            return "\n".join(parts) if parts else "(empty result)"

        try:
            return await retry_async(
                _do_call,
                attempts=settings.retry_attempts,
                backoff=settings.retry_backoff,
                retry_on=(asyncio.TimeoutError, ConnectionError, OSError),
                label=f"tool '{name}'",
            )
        except asyncio.TimeoutError:
            return f"Error: tool '{name}' timed out after {settings.tool_timeout}s"
        except Exception as exc:
            logger.error("Tool '{}' failed: {}", name, exc)
            return f"Error calling tool '{name}': {exc}"

"""
Async client for the Ollama native HTTP API.
https://3olution.com

Used by the settings page to list, pull, and delete models, and to
inspect which models are currently loaded into memory.

================================================================
  NATIVE vs OPENAI-COMPATIBLE
================================================================

  Ollama exposes two HTTP APIs on the same port:

    /api/*    — the native API (this file)
    /v1/*     — the OpenAI-compatible API (used by backend/llm.py)

  The native API is richer: it can pull models with progress
  streaming, report which models are loaded, unload them explicitly,
  and describe model architecture. The OpenAI-compatible API cannot
  do any of that — it is strictly for chat completions.

  So the agent talks to /v1/, and the settings page talks to /api/.
  Same server, two surfaces, two clients.

================================================================
  A NOTE ON httpx.delete()
================================================================

  httpx deliberately does not accept a `json=` argument on
  `.delete()`. The HTTP spec says DELETE requests have no defined
  body semantics, and httpx chose to enforce that.

  Ollama's /api/delete endpoint nonetheless requires a JSON body:

      DELETE /api/delete
      Content-Type: application/json

      {"name": "llama3.2"}

  We work around this by using the generic `.request("DELETE", ...)`
  method, which does accept json=. This is the only non-obvious bit
  in this file.
"""

from __future__ import annotations

import json
from typing import AsyncGenerator

import httpx
from loguru import logger

from .config import settings


class OllamaClient:
    """
    Thin async wrapper around Ollama's native REST API.

    Every method creates a short-lived AsyncClient. This is slightly
    less efficient than sharing one client, but it avoids the
    "client used outside its context manager" class of bugs and
    makes error handling simpler. Ollama's API is low-traffic; the
    overhead is negligible.
    """

    def __init__(self, host: str | None = None) -> None:
        self.host = (host or settings.ollama_host).rstrip("/")

    # ══════════════════════════════════════════════════════════════════
    #  Health
    # ══════════════════════════════════════════════════════════════════

    async def is_available(self) -> bool:
        """
        Return True if the Ollama server responds to /api/version.

        Uses a short timeout (3s) so the health check never blocks
        the settings page for long when Ollama is down.
        """
        try:
            async with httpx.AsyncClient(timeout=3.0) as client:
                r = await client.get(f"{self.host}/api/version")
                return r.status_code == 200
        except Exception as exc:
            logger.debug("Ollama health check failed: {}", exc)
            return False

    async def version(self) -> str | None:
        """Return the Ollama server version string, or None on failure."""
        try:
            async with httpx.AsyncClient(timeout=5.0) as client:
                r = await client.get(f"{self.host}/api/version")
                r.raise_for_status()
                return r.json().get("version")
        except Exception as exc:
            logger.warning("Ollama version fetch failed: {}", exc)
            return None

    # ══════════════════════════════════════════════════════════════════
    #  Listing
    # ══════════════════════════════════════════════════════════════════

    async def list_models(self) -> list[dict]:
        """
        Return the list of locally installed models.

        Each entry is the raw dict from Ollama's /api/tags,
        including name, size, digest, modified_at, and details
        (family, parameter_size, quantization_level, etc.).
        """
        async with httpx.AsyncClient(timeout=10.0) as client:
            r = await client.get(f"{self.host}/api/tags")
            r.raise_for_status()
            return r.json().get("models", [])

    async def show_model(self, name: str) -> dict:
        """
        Return detailed information about one model.

        Includes the modelfile, template, system prompt, and the
        full parameter list.
        """
        async with httpx.AsyncClient(timeout=10.0) as client:
            r = await client.post(
                f"{self.host}/api/show",
                json={"name": name},
            )
            r.raise_for_status()
            return r.json()

    # ══════════════════════════════════════════════════════════════════
    #  Loaded models (/api/ps)
    # ══════════════════════════════════════════════════════════════════

    async def list_loaded(self) -> list[dict]:
        """
        Return models currently loaded into memory.

        Used as a busy indicator: the frontend polls this to know
        whether a model is warm and how much VRAM it is using.
        """
        try:
            async with httpx.AsyncClient(timeout=5.0) as client:
                r = await client.get(f"{self.host}/api/ps")
                r.raise_for_status()
                return r.json().get("models", [])
        except Exception as exc:
            logger.debug("Ollama ps failed: {}", exc)
            return []

    # ══════════════════════════════════════════════════════════════════
    #  Pull (streaming)
    # ══════════════════════════════════════════════════════════════════

    async def pull_model(self, name: str) -> AsyncGenerator[dict, None]:
        """
        Stream pull progress events from Ollama.

        Ollama emits NDJSON events like:

            {"status": "pulling manifest"}
            {"status": "downloading", "digest": "...", "total": 123, "completed": 45}
            {"status": "verifying sha256 digest"}
            {"status": "writing manifest"}
            {"status": "success"}

        Yields each parsed event as a dict. Malformed lines are
        skipped — a partially corrupted progress line should not
        abort an otherwise healthy download.
        """
        async with httpx.AsyncClient(timeout=None) as client:
            async with client.stream(
                "POST",
                f"{self.host}/api/pull",
                json={"name": name, "stream": True},
            ) as response:
                response.raise_for_status()
                async for line in response.aiter_lines():
                    if not line.strip():
                        continue
                    try:
                        yield json.loads(line)
                    except json.JSONDecodeError:
                        logger.debug("Skipping non-JSON pull line: {}", line)
                        continue

    # ══════════════════════════════════════════════════════════════════
    #  Delete
    # ══════════════════════════════════════════════════════════════════

    async def delete_model(self, name: str) -> bool:
        """
        Delete a model from disk.

        Uses `client.request("DELETE", ...)` instead of `.delete()`
        because httpx's `.delete()` does not accept a `json=` kwarg,
        and Ollama's /api/delete requires a JSON body. See the module
        docstring for details.
        """
        async with httpx.AsyncClient(timeout=10.0) as client:
            r = await client.request(
                "DELETE",
                f"{self.host}/api/delete",
                json={"name": name},
            )
            r.raise_for_status()
            return True

    # ══════════════════════════════════════════════════════════════════
    #  Unload
    # ══════════════════════════════════════════════════════════════════

    async def unload_model(self, name: str) -> bool:
        """
        Unload a model from Ollama's memory.

        Implemented via /api/generate with `keep_alive: 0` — that is
        the documented way to force an unload. Ollama has no
        dedicated unload endpoint.

        Returns True on success. Never raises.
        """
        try:
            async with httpx.AsyncClient(timeout=30.0) as client:
                await client.post(
                    f"{self.host}/api/generate",
                    json={"model": name, "keep_alive": 0},
                )
            logger.info("Unloaded Ollama model: {}", name)
            return True
        except Exception as exc:
            logger.debug("Could not unload model {}: {}", name, exc)
            return False

"""
PHP execution engine.
https://3olution.com

Runs PHP scripts through a CGI-capable binary (php-cgi / php-cgi.exe)
without requiring Apache, nginx, or Java.

================================================================
  BINARY RESOLUTION
================================================================

  Search order:

    1. AGENT_PHP_BINARY, if set and pointing at an existing file.
    2. runtime/php/php-cgi.exe  (Windows portable)
       runtime/php/php-cgi      (Unix portable)
    3. runtime/php/php.exe      (Windows portable CLI fallback)
       runtime/php/php          (Unix portable CLI fallback)
    4. php-cgi / php-cgi.exe on PATH
    5. php / php.exe on PATH
    6. Known install locations (XAMPP, WAMP, Homebrew, /usr/bin)

================================================================
  PHP CONFIGURATION
================================================================

  The official Windows PHP build does NOT ship a php.ini. Without
  one, PHP loads with every extension disabled and the notes app
  cannot connect to SQLite.

  This module looks for a php.ini next to the PHP binary and passes
  it explicitly via `-c `. If no php.ini exists, it falls back
  to enabling the essential extensions via `-d` flags, so the notes
  app still works even on a PHP that was not set up by our bootstrap.

  Extensions loaded in the fallback path:

      pdo_sqlite    required for the SQLite connection
      sqlite3       companion to pdo_sqlite
      mbstring      used by mb_strlen in index.php
      openssl       used for HTTPS, hmac, hash functions
"""

import os
import shutil
import subprocess
import sys
from pathlib import Path
from typing import Any

from loguru import logger

def find_php_cgi() -> str | None:
    """Locate a CGI-capable PHP binary, or return None."""
    if settings.php_binary:
        p = Path(settings.php_binary)
        if p.exists():
            return str(p)
        logger.warning("AGENT_PHP_BINARY points to a non-existent file: {}",
                       settings.php_binary)

    for name in ("php-cgi.exe", "php-cgi"):
        p = PORTABLE_PHP_DIR / name
        if p.is_file():
            return str(p)

    for name in ("php.exe", "php"):
        p = PORTABLE_PHP_DIR / name
        if p.is_file():
            return str(p)

    for name in ("php-cgi", "php-cgi.exe"):
        found = shutil.which(name)
        if found:
            return found

    for name in ("php", "php.exe"):
        found = shutil.which(name)
        if found:
            return found

    candidates = (
        _WINDOWS_CANDIDATES if sys.platform == "win32"
        else _UNIX_CANDIDATES
    )
    for cand in candidates:
        if Path(cand).exists():
            return cand

    return None


def is_cgi_binary(php_path: str) -> bool:
    return "cgi" in Path(php_path).name.lower()


def detect_php_version(php_binary: str) -> str | None:
    try:
        result = subprocess.run(
            [php_binary, "-v"],
            capture_output=True, text=True, timeout=5,
        )
        lines = (result.stdout or "").splitlines()
        return lines[0] if lines else None
    except Exception as exc:
        logger.debug("Could not detect PHP version: {}", exc)
        return None

def _find_php_ini(php_binary: str) -> Path | None:

def _build_cgi_env(
    *, script_filename, script_name, request_method, query_string,
    content_type, content_length, document_root, server_host, server_port,
    remote_addr, extra=None,
) -> dict[str, str]:
    env = os.environ.copy()
    env.setdefault("AGENT_PHP_DB_DRIVER", settings.php_db_driver)
    env.setdefault("AGENT_PHP_SQLITE_PATH", settings.php_sqlite_path)

    env.setdefault("AGENT_PHP_DB_PORT", str(settings.php_db_port))

    env.setdefault("AGENT_PHP_DB_USER", settings.php_db_user)
    env.setdefault("AGENT_PHP_DB_PASSWORD", settings.php_db_password)

    env.update({

        "REMOTE_ADDR": remote_addr,

#  Execution

def _build_php_args(php_binary: str) -> list[str]:
    """
    Build the command-line arguments for a php-cgi invocation.

    Loads php.ini if one exists next to the binary. Otherwise falls
    back to enabling the essential extensions via -d flags, using the
    ext/ folder next to the binary.
    """
    args: list[str] = [php_binary]

    ini = _find_php_ini(php_binary)
    if ini is not None:
        args += ["-c", str(ini)]
    else:
        # Fallback: enable extensions explicitly. This works on the
        # official Windows PHP build, whose extensions live in ext/.
        php_dir = Path(php_binary).parent
        ext_dir = php_dir / "ext"
        if ext_dir.is_dir():
            args += ["-d", f"extension_dir={ext_dir}"]
            for ext in ("pdo_sqlite", "sqlite3", "mbstring", "openssl"):
                args += ["-d", f"extension={ext}"]

    args += [
        "-d", "cgi.force_redirect=0",
        "-d", "cgi.fix_pathinfo=1",
        "-d", "display_errors=1",
        "-d", "display_startup_errors=1",
        "-d", "error_reporting=E_ALL",
    ]
    return args


def execute_php(
    *, script_path, script_name, request_method="GET",
    query_string="", headers=None, body=b"", timeout=None,
) -> dict[str, Any]:
    """Execute a PHP script and return its parsed response."""
    php_binary = find_php_cgi()
    if php_binary is None:
        return {
            "status": 500,
            "headers": {"Content-Type": "text/plain; charset=utf-8"},
            "body": (b"PHP binary not found.\n"
                     b"See /api/php/status for details, or install PHP and\n"
                     b"set AGENT_PHP_BINARY in .env."),
            "stderr": "", "error": "php_not_found",
        }

    if not script_path.exists() or not script_path.is_file():
        return {
            "status": 404,
            "headers": {"Content-Type": "text/plain; charset=utf-8"},
            "body": f"PHP script not found: {script_name}".encode("utf-8"),
            "stderr": "", "error": "script_not_found",
        }

    headers = headers or {}
    extra_headers = {
        k: v for k, v in headers.items()
        if k.lower() not in ("content-length", "content-type", "host")
    }

    env = _build_cgi_env(
        script_filename=script_path,
        script_name=script_name,
        request_method=request_method,
        query_string=query_string,
        content_type=headers.get("content-type", ""),
        content_length=len(body),
        document_root=PHP_APP_DIR,
        server_host=settings.host,
        server_port=settings.port,
        remote_addr="127.0.0.1",
        extra=extra_headers,
    )

    php_args = _build_php_args(php_binary)

    try:
        result = subprocess.run(
            php_args,
            input=body,
            capture_output=True,
            timeout=timeout or settings.php_timeout,
            env=env,
            cwd=str(PHP_APP_DIR),
        )
    except subprocess.TimeoutExpired:
        logger.warning("PHP request timed out: {}", script_name)
        return {
            "status": 504,
            "headers": {"Content-Type": "text/plain; charset=utf-8"},
            "body": b"PHP script timed out.",
            "stderr": "", "error": "timeout",
        }
    except Exception as exc:
        logger.exception("PHP execution failed: {}", exc)
        return {
            "status": 500,
            "headers": {"Content-Type": "text/plain; charset=utf-8"},
            "body": f"PHP execution error: {exc}".encode("utf-8"),
            "stderr": "", "error": str(exc),
        }

    return _parse_cgi_output(result.stdout, result.stderr)


def _parse_cgi_output(stdout: bytes, stderr: bytes) -> dict[str, Any]:
    normalised = stdout.replace(b"\r\n", b"\n")

    if b"\n\n" in normalised:
        head, body = normalised.split(b"\n\n", 1)
        parsed_ok = True
    else:
        head, body = b"", normalised
        parsed_ok = False

    status = 200 if parsed_ok else 500
    headers: dict[str, str] = {}

    for raw_line in head.split(b"\n"):
        line = raw_line.decode("utf-8", errors="replace").strip()
        if not line or ":" not in line:
            continue
        name, _, value = line.partition(":")
        name = name.strip()
        value = value.strip()
        if name.lower() == "status":
            parts = value.split(None, 1)
            if parts and parts[0].isdigit():
                status = int(parts[0])
            continue
        headers[name] = value

    headers.setdefault("Content-Type", "text/html; charset=utf-8")

    return {
        "status": status,
        "headers": headers,
        "body": body,
        "stderr": stderr.decode("utf-8", errors="replace") if stderr else "",
        "error": None if parsed_ok else "no_cgi_headers",
    }

"""
Automatic installer for llama-cpp-python[server].
https://3olution.com

The llama-cpp-python package is not on PyPI as a pure-Python wheel.
It has a native extension that must be built against the local Python
AND the local GPU stack. Building from source requires a C++ compiler
and takes several minutes. To avoid that, the project ships prebuilt
wheels for common configurations:

    cpu     — CPU only
    cu118   — CUDA 11.8 (GTX 10/16, RTX 20)
    cu121   — CUDA 12.1 (older 12.x drivers)
    cu124   — CUDA 12.4 (RTX 30/40, Ada/Hopper)

This module:

  1. Detects whether llama-cpp-python is already installed.
  2. Detects the local CUDA version via nvidia-smi.
  3. Recommends the correct wheel index for this machine.
  4. Streams the pip install output as SSE so the UI can show
     progress live.
  5. Streams an uninstall for users who want to switch wheels.

================================================================
  WINDOWS CAVEAT
================================================================

  On Windows, the native DLLs of llama-cpp-python are locked while
  the package is loaded in a running process. Upgrading or
  reinstalling requires the backend to be stopped first.

  SSE stream telling the user to restart. It does not attempt to
  kill the process itself — that would be surprising.

def detect_nvidia_cuda() -> str | None:
    """
    Run `nvidia-smi` and parse the CUDA version.

    Returns e.g. "12.4", or None if nvidia-smi is not installed or
    does not report a CUDA version in its output.

    The parse looks for a line containing "CUDA Version:" — the
    exact format of nvidia-smi output varies by driver version but
    that string has been stable for a decade.
    """
    nvidia_smi = shutil.which("nvidia-smi")
    if nvidia_smi is None:
        return None

    try:
        result = subprocess.run(
            [nvidia_smi],
            capture_output=True,
            text=True,
            timeout=5,
        )
        for line in result.stdout.splitlines():
            if "CUDA Version:" in line:
                m = re.search(r"CUDA Version:\s*([0-9]+\.[0-9]+)", line)
                if m:
                    return m.group(1)
    except Exception as exc:
        logger.debug("nvidia-smi failed: {}", exc)

    return None


def recommend_wheel_index() -> tuple[str, str]:
    """
    Return (index, reason) for the best wheel on this machine.

    index is one of: cpu, cu118, cu121, cu124.
    reason is a human-readable explanation for the UI.
    """
    cuda = detect_nvidia_cuda()

    if cuda is None:
        return "cpu", "No NVIDIA GPU detected — using CPU build."

    try:
        major_str, minor_str = cuda.split(".")[:2]
        major = int(major_str)
        minor = int(minor_str)
    except Exception:
        return "cpu", f"Could not parse CUDA version '{cuda}' — using CPU build."

    if major >= 12 and minor >= 4:
        return "cu124", f"CUDA {cuda} detected — using CUDA 12.4 build."
    if major >= 12:
        return "cu121", f"CUDA {cuda} detected — using CUDA 12.1 build."
    if major == 11:
        return "cu118", f"CUDA {cuda} detected — using CUDA 11.8 build."

    return "cpu", f"CUDA {cuda} is too old — using CPU build."

async def stream_install(
    wheel_index: str,
    upgrade: bool = False,
) -> AsyncGenerator[dict, None]:
    """
    Run `pip install llama-cpp-python[server]` and yield progress.

    Events:
        {"type": "start",   "command": "...", "wheel_index": "...", "venv": "..."}
        {"type": "line",    "text": "..."}          — one pip output line
        {"type": "success", "version": "...", "gpu_offload": bool, "restart_required": true}
        {"type": "error",   "message": "..."}
        {"type": "done"}
    """
    try:
        cmd = build_pip_command(wheel_index, upgrade=upgrade)
    except ValueError as exc:
        yield {"type": "error", "message": str(exc)}
        yield {"type": "done"}
        return

    yield {
        "type": "start",
        "command": " ".join(cmd),
        "wheel_index": wheel_index,
        "venv": str(venv_path()) if in_venv() else "(system Python)",
    }

    # Build a clean environment for pip.
    env = os.environ.copy()
    env["PYTHONIOENCODING"] = "utf-8"
    env["PYTHONUTF8"] = "1"
    env["PYTHONUNBUFFERED"] = "1"
    env["PIP_DISABLE_PIP_VERSION_CHECK"] = "1"

    # Hide the console window on Windows.
    creationflags = 0
    if sys.platform == "win32":
        creationflags = subprocess.CREATE_NO_WINDOW

    try:
        proc = await asyncio.create_subprocess_exec(
            *cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.STDOUT,
            env=env,
            creationflags=creationflags,
        )
    except Exception as exc:
        yield {"type": "error", "message": f"Could not start pip: {exc}"}
        yield {"type": "done"}
        return

    # Stream pip's output line by line.
    assert proc.stdout is not None
    async for raw_line in proc.stdout:
        line = raw_line.decode("utf-8", errors="replace").rstrip("\r\n")
        if line:
            yield {"type": "line", "text": line}

    exit_code = await proc.wait()

    if exit_code == 0:
        state = detect_llama_cpp()
        yield {
            "type": "success",
            "version": state.get("version"),
            "gpu_offload": state.get("gpu_offload"),
            "restart_required": True,
        }
    else:
        yield {
            "type": "error",
            "message": (
                f"pip exited with code {exit_code}. "
                f"See the log above for details."
            ),
        }

    yield {"type": "done"}

"""
Lifecycle manager for the llama-server subprocess.
https://3olution.com

Supports two backends, chosen automatically:

  1. NATIVE llama-server.exe (preferred)
     A self-contained C++ binary from the upstream llama.cpp project.
     No Python dependency. No AVX-512 requirement in the CPU build.
     Configured via AGENT_LLAMA_CPP_BINARY, or auto-detected at
     runtime/llama-server/llama-server.exe or on PATH.

  2. PYTHON module (fallback)
     `python -m llama_cpp.server` from the llama-cpp-python package.
     Used only when no native binary is found. This path is what
     fails with 0xC000001D on CPUs without AVX-512.

The manager exposes the same interface in both cases: start, stop,
swap models, embed text, list LoRAs.

================================================================
  WHY THE NATIVE BINARY IS PREFERRED
================================================================

  The prebuilt llama-cpp-python wheels are compiled with AVX-512
  instructions. On a CPU without AVX-512 (Intel 9th gen and older,
  most 10th/11th gen desktop SKUs), the first GGML kernel that runs
  raises STATUS_ILLEGAL_INSTRUCTION (0xC000001D) and the process
  dies. The native llama.cpp binaries are compiled with the baseline
  instruction set (or AVX2, depending on which ZIP you download) and
  run on any modern x64 CPU.
"""

from pathlib import Path

def find_llama_server() -> str | None:
    """
    Return the absolute path to a native llama-server binary, or None.

    Search order:
      1. AGENT_LLAMA_CPP_BINARY (relative paths resolve against the
         project root)
      2. runtime/llama-server/llama-server.exe (portable, project-local)
      3. llama-server.exe on PATH (system-wide install)

    # 1. Explicit configuration
    if settings.llama_cpp_binary:

    for name in ("llama-server.exe", "llama-server"):
        p = PORTABLE_LLAMA_DIR / name

            return str(p)

    # 3. System PATH
    for name in ("llama-server", "llama-server.exe"):
        found = shutil.which(name)
        if found:
            return found

class LlamaServerManager:
    """
    Manages the llama-server subprocess.

    One instance is created during the FastAPI lifespan and reused
    for every request. Concurrent swaps are serialised by an
    asyncio.Lock.
    """

    def __init__(self) -> None:
        self.proc: subprocess.Popen | None = None
        self.binary_path: str | None = None
        self.backend_kind: str = "none"   # "native" | "python" | "none"
        self.base_url: str = settings.llama_cpp_base_url.rstrip("/")
        self.current_model: str | None = None
        self._current_model_path: Path | None = None
        self._lock = asyncio.Lock()

        self._output_lines: list[str] = []
        self._reader_thread: threading.Thread | None = None

    # ------------------------------------------------------------------
    #  Read-only properties
    # ------------------------------------------------------------------

    @property
    def is_running(self) -> bool:
        return self.proc is not None and self.proc.poll() is None

    @property
    def loaded_model(self) -> str | None:
        return self.current_model

    # ------------------------------------------------------------------
    #  Subprocess environment
    # ------------------------------------------------------------------

    def _build_subprocess_env(self, executable: str) -> dict[str, str]:
        """
        Build the environment for the subprocess.

        The executable's own directory is prepended to PATH so sidecar
        DLLs (ggml.dll, llama.dll, ggml-cpu.dll, etc.) are found at
        load time. On Windows, this is the only reliable way to make
        a native binary find its dependencies without registering a
        DLL directory from Python.
        """
        env = os.environ.copy()

        binary_dir = str(Path(executable).parent)
        existing = env.get("PATH", "")
        parts = existing.split(os.pathsep) if existing else []
        if binary_dir not in parts:
            parts.insert(0, binary_dir)
        env["PATH"] = os.pathsep.join(parts)

        env["PYTHONIOENCODING"] = "utf-8"
        env["PYTHONUTF8"] = "1"
        env["PYTHONUNBUFFERED"] = "1"

        return env

    # ------------------------------------------------------------------
    #  Command construction
    # ------------------------------------------------------------------

    def _build_native_command(self, binary: str, model_path: Path) -> list[str]:
        """
        Build the command line for native llama-server.exe.

        Flag reference (from llama.cpp's tools/server/README.md):

          -m, --model PATH          model file
          --host HOST               bind host
          --port PORT               bind port
          -c, --ctx-size N          context size
          -ngl, --n-gpu-layers N    GPU layers to offload
          --alias NAME              model ID advertised in /v1/models
          --api-key KEY             optional bearer token
          --embeddings              enable /v1/embeddings
          --pooling mean            pooling strategy for embeddings
          --lora PATH               load a LoRA adapter (repeatable)
        """
        cmd: list[str] = [
            binary,
            "-m", str(model_path),
            "--host", settings.llama_cpp_host,
            "--port", str(settings.llama_cpp_port),
            "-c", str(settings.llama_cpp_n_ctx),
            "-ngl", str(settings.llama_cpp_n_gpu_layers),
            "--alias", settings.llama_cpp_alias,
        ]

        if settings.llama_cpp_api_key:
            cmd += ["--api-key", settings.llama_cpp_api_key]

        if settings.llama_cpp_embedding:
            cmd += ["--embeddings", "--pooling", "mean"]

        for spec in settings.llama_cpp_lora_list:
            parts = spec.split("=", 2)
            if len(parts) >= 2:
                cmd += ["--lora", parts[1]]

        return cmd

    def _build_python_command(self, model_path: Path) -> list[str]:
        """
        Build the command line for `python -m llama_cpp.server`.

        Only used when no native binary is available. This is the path
        that crashes with 0xC000001D on CPUs without AVX-512 if the
        installed wheel requires AVX-512.
        """
        cmd: list[str] = [
            sys.executable,
            "-m", "llama_cpp.server",
            "--model", str(model_path),
            "--host", settings.llama_cpp_host,
            "--port", str(settings.llama_cpp_port),
            "--n_ctx", str(settings.llama_cpp_n_ctx),
            "--n_gpu_layers", str(settings.llama_cpp_n_gpu_layers),
            "--model_alias", settings.llama_cpp_alias,
        ]

        if settings.llama_cpp_chat_format:
            cmd += ["--chat_format", settings.llama_cpp_chat_format]

        if settings.llama_cpp_api_key:
            cmd += ["--api_key", settings.llama_cpp_api_key]

        if settings.llama_cpp_embedding:
            cmd += ["--embedding"]

        return cmd

    # ------------------------------------------------------------------
    #  Start
    # ------------------------------------------------------------------

    async def start(self, model_path: Path | None = None) -> bool:
        """Start the llama-server. Returns True on success."""
        if not settings.llama_cpp_enabled:
            logger.info("llama-cpp server disabled via config")
            return False

        if self.is_running and await self.is_ready():
            logger.info(
                "llama-cpp server already running with model '{}'",
                self.current_model or "(unknown)",
            )
            return True

        # -- Resolve the model path -----------------------------------
        ensure_models_dir()

        if model_path is None:
            if self._current_model_path is not None:
                model_path = self._current_model_path
            else:
                model_path = resolve_model_path(settings.llama_cpp_model)

        if model_path is None or not model_path.exists():
            logger.error(
                "llama-cpp: model file not found: {}\n"
                "  Looked in: {}\n"
                "  Fix: drop a .gguf file in the models folder, set "
                "AGENT_LLAMA_CPP_MODEL to its filename, or set "
                "AGENT_LLAMA_CPP_ENABLED=false to skip llama-cpp.",
                settings.llama_cpp_model,
                settings.models_path,
            )
            return False

        file_size = model_path.stat().st_size
        if file_size < 1024 * 1024:
            logger.error(
                "llama-cpp: model file looks too small ({} bytes): {}",
                file_size, model_path,
            )
            return False

        # -- Choose backend -------------------------------------------
        binary = find_llama_server()

        if binary is not None:
            self.backend_kind = "native"
            self.binary_path = binary
            cmd = self._build_native_command(binary, model_path)
            env = self._build_subprocess_env(binary)
            logger.info(
                "Spawning llama-server (native, model size {:.2f} GB, "
                "port {}, alias '{}')",
                file_size / 1e9,
                settings.llama_cpp_port,
                settings.llama_cpp_alias,
            )
            logger.debug("Command: {}", " ".join(cmd))
        elif python_module_available():
            self.backend_kind = "python"
            self.binary_path = sys.executable
            cmd = self._build_python_command(model_path)
            env = self._build_subprocess_env(sys.executable)
            logger.warning(
                "No native llama-server binary found. Falling back to "
                "the Python module. If the process crashes with "
                "0xC000001D, install the AVX2 wheel:\n"
                "    runtime\\python\\python.exe -m pip install "
                "llama-cpp-python --prefer-binary --extra-index-url "
                "https://jllllll.github.io/llama-cpp-python-cuBLAS-wheels/AVX2/cpu\n"
                "Or download a native binary from "
                "https://github.com/ggml-org/llama.cpp/releases and "
                "extract into runtime/llama-server/."
            )
            logger.debug("Command: {}", " ".join(cmd))
        else:
            logger.error(
                "llama-cpp: no backend available.\n"
                "  Either:\n"
                "    1. Download a native llama-server binary from\n"
                "       https://github.com/ggml-org/llama.cpp/releases\n"
                "       and extract into runtime/llama-server/\n"
                "    2. Install llama-cpp-python:\n"
                "       pip install llama-cpp-python --prefer-binary \\\n"
                "         --extra-index-url "
                "https://jllllll.github.io/llama-cpp-python-cuBLAS-wheels/AVX2/cpu"
            )
            return False

        # -- Record state ---------------------------------------------
        self._current_model_path = model_path
        self.current_model = model_path.name
        self._output_lines = []

        # -- Spawn ----------------------------------------------------
        creationflags = 0
        if sys.platform == "win32":
            creationflags = subprocess.CREATE_NO_WINDOW

        try:
            self.proc = subprocess.Popen(
                cmd,
                cwd=str(PROJECT_ROOT),
                env=env,
                stdout=subprocess.PIPE,
                stderr=subprocess.STDOUT,
                text=True,
                bufsize=1,
                creationflags=creationflags,
            )
        except FileNotFoundError as exc:
            logger.error(
                "llama-server could not launch: {}\n"
                "  Verify the binary exists at: {}",
                exc, binary,
            )
            self.proc = None
            return False
        except Exception as exc:
            logger.exception("llama-server launch failed: {}", exc)
            self.proc = None
            return False

        # -- Capture output -------------------------------------------
        self._reader_thread = threading.Thread(
            target=self._read_output,
            args=(self.proc,),
            daemon=True,
            name="llama-server-log-reader",
        )
        self._reader_thread.start()

        # -- Wait for readiness ---------------------------------------
        deadline = time.monotonic() + settings.llama_cpp_startup_timeout

        while time.monotonic() < deadline:
            if self.proc.poll() is not None:
                if self._reader_thread is not None:
                    self._reader_thread.join(timeout=2.0)
                self._log_subprocess_failure()
                self.proc = None
                return False

            if await self.is_ready():
                logger.info(
                    "llama-server ready at {} "
                    "(model={}, backend={}, alias={})",
                    self.base_url,
                    self.current_model,
                    self.backend_kind,
                    settings.llama_cpp_alias,
                )

"""
Linear agent loop — perceive → decide → act → repeat.
https://3olution.com

This is the orchestrator that turns a user message into a sequence
of LLM calls and tool invocations. It is a plain async generator
that yields events; the caller (a FastAPI route or a WebSocket
handler) is responsible for delivering them to the client.

================================================================
  EVENTS EMITTED
================================================================

  {"type": "token",       "content": "..."}   — a streamed token
  {"type": "thinking",    "content": "..."}   — reasoning token
  {"type": "retry",       "message": "..."}   — a retry is happening
  {"type": "fallback",    "message": "..."}   — switching to fallback
  {"type": "info",        "message": "..."}   — informational notice
  {"type": "tool_call",   "name": ..., "args": ...}
  {"type": "tool_result", "name": ..., "result": ...}
  {"type": "final",       "content": ..., "messages": [...]}

  The `final` event always appears exactly once, and terminates the
  stream. Its `messages` field is the updated conversation history
  the client should pass back on the next turn.

================================================================
  EMPTY CONTENT ON ASSISTANT MESSAGES
================================================================

  When the LLM returns only tool calls and no text, the assembled
  assistant message has empty content. Two conventions exist:

    1. OpenAI and several OpenAI-compatible servers accept
       `"content": null` on an assistant message when `tool_calls`
       is present. This is the documented OpenAI convention.

    2. llama-cpp-python's Pydantic validation requires `content` to
       be a string. Passing null raises:

           {'type': 'string_type',
            'loc': (... 'ChatCompletionRequestAssistantMessage',
                    'content'),
            'msg': 'Input should be a valid string',
            'input': None}

       and the server returns HTTP 500 with seven validation errors
       as it tries each message variant in turn.

  To satisfy both, this module emits `"content": ""` for assistant
  messages with no text. An empty string is accepted by every
  OpenAI-compatible server we have tested: OpenAI, Ollama, llama-cpp,
  vLLM, LM Studio, Groq, and Together.

================================================================
  PROVIDER ROUTING
================================================================

  The `provider` argument selects which LLM endpoint to use:

      "auto" / "primary" / "ollama"
          The primary LLM. For most users this is Ollama.

      "fallback"
          The fallback LLM, if AGENT_LLM_FALLBACK_BASE_URL is set.

      "llama_cpp" / "llamacpp" / "local"
          The locally-managed llama-cpp-python server. The agent
          performs a pre-flight check and returns a friendly error
          if the server is not running, rather than retrying a
          doomed connection three times.

================================================================
  GUARD RAILS
================================================================

  MAX_TOOL_CALLS_PER_TURN
      After this many distinct tool calls in a single turn, the
      agent stops offering tools to the LLM and forces a final
      answer.

  Duplicate call suppression
      If the LLM requests the exact same (name, args) twice in one
      turn, the second call is replaced with a canned message.

  Stream stall timeout
      If no token arrives for AGENT_STREAM_STALL_TIMEOUT seconds
      mid-stream, the turn is aborted with a clear error.

  Ollama unload on switch
      When AGENT_OLLAMA_UNLOAD_ON_SWITCH is true, switching models

def _extract_reasoning_content(delta: Any) -> str | None:
    """
    Return the reasoning_content of a streaming delta, or None.

    Reads from the direct attribute (some SDKs) or the `model_extra`
    dict (OpenAI SDK v1 with Pydantic v2). Never raises.
    """
    try:
        direct = getattr(delta, "reasoning_content", None)
        if isinstance(direct, str) and direct:
            return direct
    except Exception:
        pass

    try:
        extra = getattr(delta, "model_extra", None)
        if isinstance(extra, dict):
            value = extra.get("reasoning_content")
            if isinstance(value, str) and value:
                return value
    except Exception:
        pass

    return None

    async def run(
        self,
        user_message: str,
        history: list[dict],
        model: str | None = None,
        session_id: str | None = None,
        disable_tools: bool = False,
        provider: str = "auto",
    ) -> AsyncGenerator[dict, None]:
        """
        Run one agent turn, yielding events as they occur.

        See the module docstring for the event schema and the provider
        routing rules.
        """
        # ── llama_cpp pre-flight ─────────────────────────────────────
        if provider in _LLAMA_CPP_PROVIDERS:
            preflight = await self._preflight_llama_cpp()
            if preflight is not None:
                preflight["messages"] = list(history)
                yield preflight
                return

        # ── Ollama unload-on-switch ──────────────────────────────────
        await self._maybe_unload_previous(model, provider)

        # ── Build the message list ───────────────────────────────────
        messages: list[dict] = (
            [{"role": "system", "content": SYSTEM_PROMPT}]
            + list(history)
            + [{"role": "user", "content": user_message}]
        )

        effective_model = model or settings.llm_model
        use_tools_globally = should_use_tools(
            effective_model, request_disable=disable_tools,
        )

        tools = (
            await self.mcp.list_tools_openai()
            if use_tools_globally else None
        )

        seen_calls: set[tuple[str, str]] = set()
        total_calls = 0

        for iteration in range(settings.max_iterations):
            logger.debug(
                "Agent iteration {}/{} model={} provider={} tools={}",
                iteration + 1,
                settings.max_iterations,
                effective_model,
                provider,
                "yes" if tools else "no",
            )

            turn_tools = (
                tools
                if (tools and total_calls < MAX_TOOL_CALLS_PER_TURN)
                else None
            )
            if turn_tools is None and total_calls >= MAX_TOOL_CALLS_PER_TURN:
                logger.warning(
                    "Tool call cap reached ({}). Forcing final answer.",
                    MAX_TOOL_CALLS_PER_TURN,
                )

            # ── Run one LLM turn ─────────────────────────────────────
            content = ""
            tool_calls_buffer: dict[int, dict] = {}

            async for ev in self._run_llm_turn(
                messages, turn_tools, model, disable_tools, provider,
            ):
                if ev.get("__internal__") == "turn_failed":
                    final = {
                        "type": "final",
                        "content": ev["content"],
                        "messages": messages[1:],
                    }
                    if session_id and self.store:
                        await self.store.save(session_id, messages[1:])
                    yield final
                    return

                if ev.get("__internal__") == "turn_result":
                    content = ev["content"]
                    tool_calls_buffer = ev["tool_calls"]
                    break

                yield ev

            # ── Append the assistant message to the conversation ─────
            #
            # content is coerced to "" when empty, never None.
            #
            # Rationale: OpenAI accepts content: null on assistant
            # messages that carry tool_calls, but llama-cpp-python's
            # Pydantic validator rejects null and returns HTTP 500
            # with seven validation errors. An empty string is
            # accepted by every OpenAI-compatible server we have
            # tested.
            assistant_msg: dict = {
                "role": "assistant",
                "content": content or "",
            }
            if tool_calls_buffer:
                assistant_msg["tool_calls"] = [
                    {
                        "id": buf["id"],
                        "type": "function",
                        "function": {
                            "name": buf["name"],
                            "arguments": buf["arguments"],
                        },
                    }
                    for buf in tool_calls_buffer.values()
                ]
            messages.append(assistant_msg)

            # ── No tool calls → final answer ─────────────────────────
            if not tool_calls_buffer:
                final = {
                    "type": "final",
                    "content": content or "",
                    "messages": messages[1:],
                }
                if session_id and self.store:
                    await self.store.save(session_id, messages[1:])
                yield final
                return

            # ── Execute tool calls ───────────────────────────────────
            for buf in tool_calls_buffer.values():
                name = buf["name"]
                raw_args = buf["arguments"] or "{}"

                try:
                    parsed = json.loads(raw_args) if raw_args else {}
                except json.JSONDecodeError:
                    parsed = {}

                key = (name, json.dumps(parsed, sort_keys=True))

                if key in seen_calls:
                    logger.warning(
                        "Skipping duplicate tool call: {}({})",
                        name, raw_args,
                    )
                    result = (
                        f"(skipped: {name} was already called with these "
                        f"exact arguments in this turn — produce a final "
                        f"answer now)"
                    )
                    yield {
                        "type": "tool_result",
                        "name": name,
                        "result": result,
                    }
                    messages.append({
                        "role": "tool",
                        "tool_call_id": buf["id"],
                        "content": result,
                    })
                    continue

                seen_calls.add(key)
                total_calls += 1

                yield {
                    "type": "tool_call",
                    "name": name,
                    "args": raw_args,
                }

                try:
                    result = await self.mcp.call_tool(name, parsed)
                except Exception as exc:
                    logger.exception("Tool '{}' raised", name)
                    result = f"Error calling tool '{name}': {exc}"

                yield {
                    "type": "tool_result",
                    "name": name,
                    "result": result,
                }

                messages.append({
                    "role": "tool",
                    "tool_call_id": buf["id"],
                    "content": result,
                })

        # ── Max iterations reached ───────────────────────────────────
        final = {
            "type": "final",
            "content": (
                f"Reached max iterations ({settings.max_iterations}) "
                "without a final answer. Try rephrasing or increasing "
                "AGENT_MAX_ITERATIONS."
            ),
            "messages": messages[1:],
        }
        if session_id and self.store:
            await self.store.save(session_id, messages[1:])
        yield final

    #  Internal: one LLM turn
    # ══════════════════════════════════════════════════════════════════

    async def _run_llm_turn(
        self,
        messages: list[dict],
        tools: list[dict] | None,
        model: str | None,
        disable_tools: bool,
        provider: str,
    ) -> AsyncGenerator[dict, None]:
        """
        Run one LLM turn with retries, fallback, and tool-support
        fallback.

        Yields token / thinking / retry / fallback events, then a
        sentinel dict with `__internal__` set to either "turn_result"
        or "turn_failed".
        """
        effective_model = model or settings.llm_model
        allow_tools = (
            tools
            if (tools and should_use_tools(effective_model, disable_tools))
            else None
        )

        primary_error: Exception | None = None
        fallback_error: Exception | None = None

        # ── Phase 1: primary provider ────────────────────────────────
        attempt = 0
        while attempt < settings.retry_attempts:
            try:
                state: dict[str, Any] = {"content": "", "tool_calls": {}}
                async for ev in self._consume_stream(
                    self.llm.chat_stream(
                        messages,
                        tools=allow_tools,
                        model=model,
                        provider=provider,
                        disable_tools=disable_tools,
                    ),
                    state,

                    yield ev

                yield {
                    "__internal__": "turn_result",
                    "content": state["content"],
                    "tool_calls": state["tool_calls"],
                }
                return

                    yield {

                        "message": (
                            f"Model '{effective_model}' does not support "
                            f"tool use. Continuing without tools."
                        ),
                    }
                    allow_tools = None
                    continue
                primary_error = exc
                break

                if not is_retryable(exc):
                    primary_error = exc
                    break
                primary_error = exc
                attempt += 1
                if attempt < settings.retry_attempts:
                    wait = settings.retry_backoff * (2 ** (attempt - 1))
                    logger.warning(
                        "Primary LLM failed (attempt {}/{}): {}. "
                        "Retrying in {:.1f}s…",
                        attempt, settings.retry_attempts, exc, wait,
                    )
                    yield {

                        "message": (
                            f"LLM connection failed — retrying "
                            f"(attempt {attempt + 1}/"
                            f"{settings.retry_attempts})…"
                        ),

            provider not in _LLAMA_CPP_PROVIDERS
            and settings.fallback_enabled
            and self.llm.fallback is not None

            yield {
                "type": "fallback",
                "message": (
                    f"Primary LLM unavailable — switching to fallback "
                    f"({fb_model}). Reason: {primary_error}"
                ),
            }

                else None
            )

                        self.llm.chat_stream_fallback(

                            model=None,

                        ),

                            ),

        msg = f"Primary LLM error: {primary_error}"
        if fallback_error is not None:

        elif (
            not settings.fallback_enabled
            and provider not in _LLAMA_CPP_PROVIDERS

            msg += (
                "\nNo fallback LLM configured. Set "
                "AGENT_LLM_FALLBACK_BASE_URL in .env to enable failover."
            )

        yield {"__internal__": "turn_failed", "content": msg}

    # ══════════════════════════════════════════════════════════════════
    #  Internal: consume one delta stream
    # ══════════════════════════════════════════════════════════════════

    async def _consume_stream(
        self,
        stream,
        state: dict[str, Any],
    ) -> AsyncGenerator[dict, None]:
        """
        Consume one streaming response, emitting thinking and token
        events as they arrive.

        Mutates `state` in place:

            state["content"]     — the final-answer text so far
            state["tool_calls"]  — {index: {id, name, arguments}}

        Reasoning tokens are NOT added to state["content"]. That
        means reasoning never leaks into the persisted conversation
        history.
        """
        show_thinking = settings.show_thinking
        splitter = ThinkingSplitter(enabled=show_thinking)

        tool_calls_buffer: dict[int, dict] = {}
        content_accum = ""
        last_event_at = time.monotonic()
        stall_timeout = settings.stream_stall_timeout
        got_any = False

        try:
            async for delta in stream:
                got_any = True
                last_event_at = time.monotonic()

                # ── DeepSeek-style separate reasoning field ──────────
                reasoning = _extract_reasoning_content(delta)
                if reasoning and show_thinking:
                    yield {"type": "thinking", "content": reasoning}

                # ── Standard content, possibly with inline markers ──
                if delta.content:
                    for kind, content in splitter.feed(delta.content):
                        if kind == "thinking":
                            if show_thinking:
                                yield {
                                    "type": "thinking",
                                    "content": content,
                                }
                        else:
                            content_accum += content
                            if settings.stream_tokens:
                                yield {
                                    "type": "token",
                                    "content": content,
                                }

                # ── Tool call deltas ─────────────────────────────────
                if delta.tool_calls:
                    for tc in delta.tool_calls:
                        idx = tc.index if tc.index is not None else 0
                        if idx not in tool_calls_buffer:
                            tool_calls_buffer[idx] = {
                                "id": "",
                                "name": "",
                                "arguments": "",
                            }
                        buf = tool_calls_buffer[idx]
                        if tc.id:
                            buf["id"] = tc.id
                        if tc.function:
                            if tc.function.name:
                                buf["name"] = tc.function.name
                            if tc.function.arguments:
                                buf["arguments"] += tc.function.arguments

                # ── Stall detection ──────────────────────────────────
                if time.monotonic() - last_event_at > stall_timeout:
                    raise TimeoutError(
                        f"No tokens received for {stall_timeout:.0f}s. "
                        f"Aborting turn."
                    )

        finally:
            try:
                await stream.aclose()
            except Exception:
                pass

        # ── Flush the splitter's tail ────────────────────────────────
        for kind, content in splitter.flush():
            if kind == "thinking":
                if show_thinking:
                    yield {"type": "thinking", "content": content}
            else:
                content_accum += content
                if settings.stream_tokens:
                    yield {"type": "token", "content": content}

        if not got_any:
            raise RuntimeError("LLM stream returned no chunks")

        state["content"] = content_accum
        state["tool_calls"] = tool_calls_buffer

    """Download LiteGraph vendor files if missing. Never raises."""
    if _vendor_files_ok():
        logger.info("LiteGraph vendor files present")
        return True

    if not DOWNLOAD_SCRIPT.exists():
        logger.warning(
            "Download script not found: {}. "
            "The graph editor will fall back to a CDN.",
            DOWNLOAD_SCRIPT,

    try:
        result = subprocess.run(
            [sys.executable, str(DOWNLOAD_SCRIPT)],
            capture_output=True,
            text=True,
            timeout=90,

            logger.info("LiteGraph vendor files downloaded successfully")
            return True
        logger.warning(
            "Vendor download returned code {}. stderr: {}",
            result.returncode,
            (result.stderr or "").strip()[:500],

        logger.warning("Vendor download timed out after 90s")

        logger.warning("Vendor download failed: {}", exc)

        "Continuing without local vendor files. "

            names = [m["name"] for m in loaded if m.get("name")]

        ok = await client.unload_model(name)
        if ok:
            unloaded.append(name)
        else:
            errors.append({"name": name, "error": "unload failed"})

    Streams Ollama's NDJSON progress events as Server-Sent Events.
    Each frame is a `data: {...}` line. The stream ends with
    `data: [DONE]`.

    On error, emits a single frame with an `error` field, then the

    needing to distinguish error frames from progress frames — it
    checks for the `error` key.

        try:
            async for event in client.pull_model(req.name):
                yield f"data: {json.dumps(event)}\n\n"
        except Exception as exc:
            logger.exception("Pull failed for {}", req.name)
            err = json.dumps({"error": str(exc)})
            yield f"data: {err}\n\n"
        finally:
            yield "data: [DONE]\n\n"

    return StreamingResponse(
        event_stream(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # disable nginx buffering
            "Connection": "keep-alive",

System control and log access.
https://3olution.com

Endpoints:

    GET  /api/system/status     -- live subsystem state
    POST /api/system/stop-all   -- stop llama-cpp, MCP, and self
    GET  /api/logs/files        -- list log files
    GET  /api/logs/recent       -- tail the most recent log lines

================================================================
  STOP-ALL SEMANTICS
================================================================

  POST /api/system/stop-all returns immediately with a JSON
  acknowledgement, then terminates every subsystem in a background
  task. It does NOT wait for the shutdown to complete.

  Why: the HTTP response must be delivered BEFORE the process
  exits, otherwise the client sees a connection reset instead of
  a clean 200. We schedule the shutdown on the next tick, send the
  response, and only then actually shut down.

  On Unix, the process terminates with SIGTERM (caught by uvicorn
  and re-raised as a clean exit). On Windows, os._exit(0) is used
  because there is no equivalent signal and uvicorn's graceful
  shutdown is unreliable when triggered from within a request
  handler.

================================================================
  LOG READING
================================================================

  The log viewer in the desktop client and the settings page uses
  /api/logs/recent. It reads the tail of the newest matching log
  file. It does NOT stream -- the client polls every few seconds
  when the viewer is open.

  Line count is clamped to 5000 to prevent a runaway client from
  reading a multi-gigabyte log file into memory.

  COMPATIBILITY
================================================================

      settings.logs_path       (backend/config.py)

@router.post("/system/stop-all")
async def stop_all():
    """
    Stop every process the backend manages, then exit.

    Returns a JSON acknowledgement immediately; the actual shutdown
    runs in a background task.

    Order matters:

      1. Stop llama-cpp first. It owns the largest allocation and
         should release its memory before the MCP subprocess tears
         down.
      2. Close the MCP session cleanly.
      3. Terminate the backend process itself.
    """
    logger.warning("Stop-all requested from API. Shutting everything down...")

    async def _shutdown() -> None:
        # Give the HTTP response time to reach the client.
        await asyncio.sleep(0.8)

        # ── llama-cpp ───────────────────────────────────────────────
        llama = state.get("llama_server")
        if llama is not None:
            try:
                await llama.stop()
                logger.info("llama-cpp server stopped")
            except Exception as exc:
                logger.warning("Error stopping llama-cpp server: {}", exc)

        # ── MCP ─────────────────────────────────────────────────────
        mcp = state.get("mcp")
        if mcp is not None:
            try:
                await mcp.close()
                logger.info("MCP session closed")
            except Exception as exc:
                logger.warning("Error closing MCP: {}", exc)

        # ── Self ────────────────────────────────────────────────────
        logger.info("Terminating backend process")
        try:
            if sys.platform == "win32":
                # os._exit bypasses atexit handlers; nothing left to clean up.
                os._exit(0)
            else:
                os.kill(os.getpid(), signal.SIGTERM)
        except Exception:
            os._exit(0)

    asyncio.create_task(_shutdown())

    return {
        "status": "stopping",
        "message": "Backend is shutting down.",
    }

async def recent_logs(lines: int = 500, source: str = "all"):
    """
    Return the tail of the newest log file.

    Query parameters:
        lines   Maximum number of lines to return. Clamped to [1, 5000].
        source  "backend" | "desktop" | "all". Selects which file
                pattern to look for: backend-*.log, desktop-*.log,
                or both.

    The response is a list of strings, one per line, with trailing
    newlines stripped. It includes the file name and total line count
    so the client can show "(showing last 500 of 12034 lines)".
    """
    lines = max(1, min(lines, 5000))

    log_dir = settings.logs_path
    if not log_dir.exists():
        return {"lines": [], "source": source}

    if source == "backend":
        patterns = ["backend-*.log"]
    elif source == "desktop":
        patterns = ["desktop-*.log"]
    else:
        patterns = ["backend-*.log", "desktop-*.log"]

    files: list[Path] = []
    for pat in patterns:
        files.extend(log_dir.glob(pat))

    if not files:
        return {"lines": [], "source": source}

    # Sort by modification time, newest first, and take the latest.
    files.sort(key=lambda p: p.stat().st_mtime, reverse=True)
    latest = files[0]

    try:
        with latest.open("r", encoding="utf-8", errors="replace") as f:
            all_lines = f.readlines()
    except Exception as exc:
        raise HTTPException(
            status_code=500,
            detail=f"Could not read log file: {exc}",
        )

    tail = all_lines[-lines:]

    return {
        "lines": [line.rstrip("\n") for line in tail],
        "file": latest.name,
        "source": source,
        "total_lines": len(all_lines),
        "shown_lines": len(tail),
    }

================================================================

  Starlette matches routes in registration order. There are two
  potential collisions to avoid:

    1. /php-static/{asset} vs /php/{path}
       These do NOT collide because Starlette's path converter
       requires a literal slash after "/php". A path starting with
       "/php-static" has a hyphen where the slash would be, so it
       does not match "/php/{path}".

    2. /api/php/status vs /php/{path}
       These also do not collide — the /api prefix is registered
       before the catch-all.

  module, as defensive practice.

================================================================

  Every user-supplied path is resolved under the PHP app directory.
  A path like "../../etc/passwd" is rejected with HTTP 400 before
  the file is even opened.

  The check is done by resolving the candidate to its canonical
  form and verifying that the result is a subpath of the app
  directory. This is the standard defence against directory
  traversal.

def _resolve_safe(rel_path: str) -> Path | None:
    """
    Resolve a request path to an absolute file under PHP_APP_DIR.

    Returns None if:
        - the resolved path escapes PHP_APP_DIR
        - the resolved path does not end in ".php"

    Empty rel_path resolves to "index.php".
    """
    if not rel_path:
        rel_path = "index.php"

    if not rel_path.endswith(".php"):
        rel_path += ".php"

    base = PHP_APP_DIR.resolve()
    candidate = (base / rel_path).resolve()

    try:
        candidate.relative_to(base)
    except ValueError:
        logger.warning("Rejected path traversal attempt: {}", rel_path)
        return None

    return candidate


def _resolve_static_safe(asset: str) -> Path | None:
    """
    Resolve a static asset path under PHP_STATIC_DIR.

    Returns None if the path escapes the static directory or does
    not exist as a regular file.
    """
    base = PHP_STATIC_DIR.resolve()
    candidate = (base / asset).resolve()

    try:
        candidate.relative_to(base)
    except ValueError:
        logger.warning("Rejected static path traversal attempt: {}", asset)
        return None

    if not candidate.is_file():
        return None

    return candidate

    query_string = request.url.query or ""
    body = await request.body()
    headers = dict(request.headers)

    if php_path:
        script_name = f"/php/{php_path}"
        if not script_name.endswith(".php"):

        script_name = "/php/index.php"

    @classmethod
    def from_dict(cls, data: dict) -> "Graph":
        node_fields = {"id", "type", "inputs", "params", "position", "title"}
        edge_fields = {"id", "from_node", "from_output", "to_node", "to_input"}

        nodes = []
        for n in data.get("nodes", []):
            filtered = {k: v for k, v in n.items() if k in node_fields}
            if "pos" in n and "position" not in filtered:
                filtered["position"] = tuple(n["pos"])
            nodes.append(Node(**filtered))

        edges = [
            Edge(**{k: v for k, v in e.items() if k in edge_fields})
            for e in data.get("edges", [])
        ]

        return cls(
            id=data.get("id", "default"),
            name=data.get("name", "Untitled"),
            nodes=nodes,
            edges=edges,
        )

def _decode_model_and_provider(
    raw_model: str | None,
    raw_provider: str | None,
) -> tuple[str | None, str]:
    """
    Return (model, provider) from the two widget values.

    The `model` widget can hold three things:

        ""                    → no model; use AGENT_LLM_MODEL
        "(default)"           → same as above
        "provider::model"     → the encoded form the frontend sends
        "model"               → a bare model name (legacy / hand-edited)

    When the encoded form is present, the provider it carries wins over
    the `provider` widget. This is deliberate: the user picked a
    specific model from a specific provider, so that choice should not
    be silently overridden by a stale widget value.

    The returned provider is always a lowercase string; it may be
    "auto", "ollama", "llama_cpp", or "fallback". Empty values fall
    back to "auto".
    """
    provider = (raw_provider or "").strip().lower() or "auto"
    model: str | None = None

    raw = (raw_model or "").strip()
    if raw and raw not in ("(default)",):
        if "::" in raw:
            prov_part, model_part = raw.split("::", 1)
            prov_part = prov_part.strip().lower()
            model_part = model_part.strip()
            if prov_part:
                provider = prov_part
            if model_part:
                model = model_part
        else:
            model = raw

    return model, provider


async def _llm_chat(ctx, inputs, params):
    """
    Send a message list to an LLM and return the reply.

    Supports all three providers:

        primary   (ollama, openai, lm-studio, …)
        fallback  (an optional secondary endpoint)
        llama_cpp (the local llama-cpp-python server)

    The provider is resolved from the `model` widget's encoded prefix,
    falling back to the `provider` widget, falling back to "auto".
    """
    llm = ctx.app.get("llm")
    if llm is None:
        raise RuntimeError("LLM client not available in app state.")

    # ── Build the message list ───────────────────────────────────────
    messages = inputs.get("messages")
    if not messages:
        messages = params.get("messages") or [
            {"role": "user", "content": "Hello"}
        ]
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]

    # ── Decode provider and model ────────────────────────────────────
    model, provider = _decode_model_and_provider(
        params.get("model"),
        params.get("provider"),
    )

    # ── Resolve tools ────────────────────────────────────────────────
    tools = inputs.get("tools") or None
    disable_tools = bool(params.get("disable_tools", False))

    # ── Call the LLM ─────────────────────────────────────────────────
    response = await llm.chat(
        messages,
        tools=tools,
        model=model,
        provider=provider,
        disable_tools=disable_tools,
    )

    msg = response.choices[0].message

    tool_calls = []
    for tc in (msg.tool_calls or []):
        tool_calls.append({
            "id": tc.id,
            "name": tc.function.name,
            "arguments": tc.function.arguments,
        })

    return {
        "response": msg.content or "",
        "tool_calls": tool_calls,
        "raw": msg.model_dump(exclude_none=True),
    }

"""
Topological execution engine for the dynamic operating graph.
"""

import json
from typing import Any, AsyncGenerator

from loguru import logger

from . import registry
from .model import Graph, Node


class ExecutionContext:
    """Holds outputs and app state during a graph run."""

    def __init__(self, graph: Graph, app_state: dict) -> None:
        self.graph = graph
        self.app = app_state
        self.outputs: dict[str, dict] = {}
        self.status: dict[str, str] = {}


def _topo_sort(graph: Graph) -> list[str]:
    """Kahn's algorithm — returns node IDs in execution order."""
    indeg: dict[str, int] = {n.id: 0 for n in graph.nodes}
    adj: dict[str, list[str]] = {n.id: [] for n in graph.nodes}

    for e in graph.edges:
        if e.from_node in adj and e.to_node in indeg:
            adj[e.from_node].append(e.to_node)
            indeg[e.to_node] += 1

    queue = [nid for nid, d in indeg.items() if d == 0]
    order: list[str] = []

    while queue:
        nid = queue.pop(0)
        order.append(nid)
        for m in adj[nid]:
            indeg[m] -= 1
            if indeg[m] == 0:
                queue.append(m)

    if len(order) != len(graph.nodes):
        raise ValueError(
            "Graph contains a cycle. Only DAGs are supported in v1. "
            "Use control.foreach for iteration."
        )
    return order


def _gather_inputs(graph: Graph, node: Node, ctx: ExecutionContext) -> dict:
    """Collect a node's inputs from static values and upstream outputs."""
    inputs = dict(node.inputs)
    for e in graph.edges:
        if e.to_node == node.id:
            src = ctx.outputs.get(e.from_node, {})
            inputs[e.to_input] = src.get(e.from_output)
    return inputs


def _safe(v: Any) -> Any:
    """Ensure a value is JSON-serialisable."""
    try:
        json.dumps(v)
        return v
    except (TypeError, ValueError):
        return str(v)


async def execute(graph: Graph, app_state: dict) -> AsyncGenerator[dict, None]:
    """Run a graph and yield progress events."""
    ctx = ExecutionContext(graph, app_state)
    node_by_id = {n.id: n for n in graph.nodes}

    try:
        order = _topo_sort(graph)
    except ValueError as exc:
        yield {"type": "graph_error", "error": str(exc)}
        return

    yield {"type": "graph_start", "order": order}

    for node_id in order:
        node = node_by_id[node_id]
        nt = registry.get(node.type)

        if nt is None or nt.fn is None:
            yield {
                "type": "node_error",
                "node": node_id,
                "error": f"Unknown node type: {node.type}",
            }
            continue

        yield {"type": "node_start", "node": node_id}
        inputs = _gather_inputs(graph, node, ctx)

        try:
            result = await nt.fn(ctx, inputs, node.params or {})
        except Exception as exc:
            logger.exception("Node '{}' ({}) failed", node_id, node.type)
            yield {"type": "node_error", "node": node_id, "error": str(exc)}
            ctx.outputs[node_id] = {}
            ctx.status[node_id] = "error"
            continue

        ctx.outputs[node_id] = result or {}
        ctx.status[node_id] = "done"

        preview: dict[str, str] = {}
        for k, v in (result or {}).items():
            try:
                s = json.dumps(v, default=str)
            except (TypeError, ValueError):
                s = str(v)
            preview[k] = s[:400]

        yield {"type": "node_done", "node": node_id, "outputs": preview}

    yield {
        "type": "graph_done",
        "outputs": {
            nid: {k: _safe(v) for k, v in outs.items()}
            for nid, outs in ctx.outputs.items()
        },
    }

def _extract_final_text(events: list[dict], outputs: dict) -> str | None:
    """
    Return the text from the first output.text node in the final
    outputs map, or None if no output.text node produced a result.
    """
    for node_id, outs in (outputs or {}).items():
        if isinstance(outs, dict) and "result" in outs:
            result = outs["result"]
            if result:
                return str(result)
    return None


def _summarize_status(events: list[dict]) -> str:
    """Return 'ok' or 'error' based on the event stream."""
    for ev in events:
        t = ev.get("type")
        if t in ("graph_error", "node_error"):
            return "error"
    return "ok"

@router.post("/api/graph/run")
async def graph_run(payload: dict):
    """
    Execute a graph synchronously and return all events.

    The run is saved to the graph_runs table before the response is
    returned. The response includes the run_id in a trailing event
    so the client can fetch the record later.
    """
    graph = Graph.from_dict(payload)
    events: list[dict] = []

    async for ev in execute(graph, state):
        events.append(ev)

    # Collect the final outputs to compute final_text and status.
    outputs = {}
    for ev in events:
        if ev.get("type") == "graph_done":
            outputs = ev.get("outputs", {})

    final_text = _extract_final_text(events, outputs)
    status = _summarize_status(events)

    # Persist the run.
    store = state.get("store")
    if store is not None:
        try:
            run_id = await store.save_run(payload, events, status, final_text)
            events.append({"type": "run_saved", "run_id": run_id})
        except Exception as exc:
            logger.warning("Could not save graph run: {}", exc)

    return JSONResponse(events)


@router.websocket("/ws/graph")
async def graph_ws(websocket: WebSocket):
    """Execute a graph, streaming progress events over WebSocket."""
    await websocket.accept()
    try:
        while True:
            payload = await websocket.receive_json()
            graph = Graph.from_dict(payload)

            events: list[dict] = []
            async for ev in execute(graph, state):
                events.append(ev)
                await websocket.send_json(ev)

            # Persist after execution completes.
            outputs = {}
            for ev in events:
                if ev.get("type") == "graph_done":
                    outputs = ev.get("outputs", {})

            final_text = _extract_final_text(events, outputs)
            status = _summarize_status(events)

            store = state.get("store")
            if store is not None:
                try:
                    run_id = await store.save_run(
                        payload, events, status, final_text,
                    )
                    await websocket.send_json({
                        "type": "run_saved",
                        "run_id": run_id,
                    })
                except Exception as exc:
                    logger.warning("Could not save graph run: {}", exc)

    except WebSocketDisconnect:
        return
    except Exception as exc:
        logger.exception("Graph WebSocket error")
        try:
            await websocket.send_json(
                {"type": "graph_error", "error": str(exc)}
            )
        except Exception:
            pass

Guard rails summary

The agent applies four independent guard rails to keep small models from looping or hanging:

GuardTriggerEffect
Duplicate suppressionSame (tool_name, args) twice in one turnSecond call replaced with "produce a final answer" message
Tool call capMAX_TOOL_CALLS_PER_TURN (6) reachedTools stripped from subsequent LLM calls; final answer forced
Stream stallNo token for AGENT_STREAM_STALL_TIMEOUT (360 s)Turn aborts with TimeoutError

Each guard is independent. A model that calls tools 6 times, then loops the same tool, then stalls, then exceeds iterations will hit each guard in turn and produce a coherent error rather than hanging.
