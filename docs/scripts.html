Scripts Folder

Five small programs that sit between the user and the backend. Two of them are launch helpers — serve.py starts uvicorn with three Windows/console fixes applied, and llama_cpp_runner.py launches the llama_cpp.server module while bypassing its broken argument parser. The other three are the LiteGraph vendor downloader, in three flavours: a full-featured Python version and two thin shell wrappers for environments without Python.

Overview

The scripts/ folder contains the programs that launch the backend and fetch the one external asset the graph editor needs. They are not part of the FastAPI application — they are what runs the application. None of them is imported by backend/; each is a standalone entry point.

What lives here

FilePurpose
serve.py Uvicorn entry point with three cross-platform fixes applied
download_vendor.py Cross-platform LiteGraph downloader with mirror fallback and two validation gates
download_vendor.sh Bash wrapper — for environments with curl but no Python
download_vendor.ps1 PowerShell wrapper — for Windows users who prefer not to invoke Python directly
llama_cpp_runner.py Direct runner for llama_cpp.server that bypasses the module's argument parser

How the launchers stack

start.sh / start.bat        ← user-facing portable launchers
        │
        └── run.py backend     ← developer launcher
                │
                └── scripts/serve.py    ← uvicorn entry point
                        │
                        └── backend.main:app   ← the FastAPI application

(Optional, spawned by the backend at startup:)
backend/llama_server.py
        │
        └── scripts/llama_cpp_runner.py   ← llama_cpp.server replacement

The user normally interacts with the top of that stack. Each lower layer is a fallback: if run.py is not available, run serve.py directly; if neither is, run uvicorn directly on backend.main:app (losing the three fixes described below).

Why these are separate files

Each of them fixes a problem that is:

  • Easy to miss. The symptom is subtle — a random MCP handshake failure, a ModuleNotFoundError only in the reloader child, thousands of duplicate log lines.
  • Hard to diagnose. The cause is not in the code that fails; it is in how the process was launched.
  • Not portable to fix in backend/. The fixes have to run before the app is imported, before uvicorn creates its event loop, and before the reloader spawns its child process.

Bundling them into a script that the user runs, rather than distributing instructions, is the difference between a project that works out of the box and a project that requires a wiki page of gotchas.

Which file should I use?

TaskCommand
Start the backend (normal) ./start.sh or start.bat
Start the backend (dev, with reload) python run.py backend
Start the backend (bypass all wrappers) python scripts/serve.py
Fetch LiteGraph (normal) python scripts/download_vendor.py
Fetch LiteGraph (no Python available) bash scripts/download_vendor.sh or powershell scripts\download_vendor.ps1
Debug llama-cpp startup runtime/python/python.exe scripts/llama_cpp_runner.py
Nothing in this folder imports from backend/. Each file is self-contained. This is deliberate — it means you can copy a single script to another machine and it will still work, and it means a syntax error in one script cannot break the backend.

Related folders

  • bootstrap/ — sets up runtime/ (Python, PHP, SQLite)
  • backend/ — the FastAPI application that serve.py launches
  • runtime/ — the portable binaries these scripts invoke
  • web/vendor/ — where download_vendor.py writes its output

serve.py — the three fixes

serve.py is a thin wrapper around uvicorn.run(). If you have ever run uvicorn backend.main:app directly and hit one of three specific problems, this file is the fix.

ProblemFixWhere
Windows event loop breaks MCP stdio Set SelectorEventLoopPolicy before importing uvicorn Lines at module top
Reloader child cannot find backend Set both sys.path and PYTHONPATH before importing uvicorn Lines at module top
Access log floods the log sink Disabled unless AGENT_UVICORN_ACCESS_LOG=1 In uvicorn.run(...) call

The order of operations matters: the loop policy must be set before import uvicorn, and sys.path / PYTHONPATH must be set before uvicorn spawns its reloader child. Both are done at module top, guarded so a double-import does not duplicate the entries.

Fix 1 — Windows event loop

On Windows, Python 3.8+ defaults to ProactorEventLoop. Proactor supports asyncio.create_subprocess_exec but has known bugs reading from subprocess pipes. The MCP SDK's stdio transport reads from pipes continuously, so the MCP handshake fails roughly one time in five.

The fix is to switch to SelectorEventLoop, which has reliable pipe reading. It lacks create_subprocess_exec, but uvicorn does not use that for its default HTTP/WebSocket transports (they use sockets, which Selector handles fine). The MCP SDK dispatches its own subprocess creation internally, so it works under either policy.

Crucially, the policy must be set before import uvicorn — uvicorn creates its loop at import time, so setting the policy afterwards has no effect. 

if sys.platform == "win32":
    asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())

import uvicorn  # must come after

Fix 2 — sys.path for the reloader child

Running python scripts/serve.py puts scripts/ on sys.path[0], not the project root. When uvicorn with --reload spawns a child process, that child re-imports backend.main — and fails with ModuleNotFoundError because the project root is not on its sys.path.

Two things are needed:

  • sys.path in this process (for direct imports).
  • PYTHONPATH in the environment (for the child process).
Windows-specific gotcha. Windows uses multiprocessing spawn for the reloader child, which does not inherit sys.path mutations from the parent. Only the environment variable survives. Both must be set. 
PROJECT_ROOT = Path(__file__).resolve().parent.parent
_root_str = str(PROJECT_ROOT)

if _root_str not in sys.path:
    sys.path.insert(0, _root_str)

_existing_pp = os.environ.get("PYTHONPATH", "")
if _root_str not in _existing_pp.split(os.pathsep):
    os.environ["PYTHONPATH"] = (
        _root_str + (os.pathsep + _existing_pp if _existing_pp else "")
    )

The guards (if not in) make this idempotent. Importing the module twice — or running it under a launcher that already set PYTHONPATH — does not duplicate the entry.

Fix 3 — access log noise

Uvicorn's per-request access log is verbose. The web UI polls /api/health, /api/ollama/ps, and /api/llama/runtime/status every few seconds while a page is open. In a four-hour session that is thousands of identical INFO: ... "GET /api/health HTTP/1.1" 200 OK lines — a real problem for the desktop log dock and the rotating file sink.

Access logging is disabled by default. To re-enable, set AGENT_UVICORN_ACCESS_LOG=1 in .env. 

ACCESS_LOG = os.environ.get("AGENT_UVICORN_ACCESS_LOG", "0") == "1"

uvicorn.run(
    ...,
    access_log=ACCESS_LOG,
)

4xx and 5xx lines are not suppressed by this mechanism — they are written by the app's own logger, not uvicorn's access log. Those still appear and are still worth paying attention to.

Configuration variables

VariableDefaultMeaning

AGENT_LOG_LEVELinfoUvicorn log level

Running serve.py directly

python scripts/serve.py

This is the same as running python run.py backend with no reload flag, or ./start.sh. All three eventually call uvicorn.run with the three fixes applied.

The fix is a no-op on Linux and macOS. The event loop policy is Windows-only. On Unix, serve.py's only real job is the sys.path / PYTHONPATH dance — and even that is more forgiving because Unix spawn inherits more state than Windows spawn.

download_vendor.py — the algorithm

The downloader fetches two files from the jagenjo/litegraph.js repository into web/vendor/. Nothing more complicated than that — except for two validation gates and a mirror fallback, which together make the operation trustworthy.

The pseudocode

for each file (litegraph.min.js, litegraph.css):
    if file exists and size >= MIN_SIZE:
        skip

    for each mirror URL:
        try download
        if downloaded size < MIN_SIZE:
            reject, try next mirror
        if REQUIRED_SUBSTRING not in content:
            reject, try next mirror
        write to disk
        return success

    return failure

Why two gates

A naive downloader writes whatever the server returns. That works 99% of the time and fails in three specific ways the other 1%.

Gate 1 — size floor

A 404 HTML page is a few KB. A captive-portal login page is similar. If you write either to web/vendor/litegraph.min.js, the graph editor loads a file that contains an HTML error page instead of JavaScript, and every attempt to use it fails with a confusing syntax error.

The minimum-size check rejects anything smaller than expected:

FileMinimum sizeActual size
litegraph.min.js50,000 bytes~85 KB
litegraph.css1,000 bytes~4 KB

Gate 2 — required substring

A captive portal can return a 200 with a full-sized error page. A proxy can rewrite content. A CDN can serve a cached redirect. The size check alone would not catch these.

So the downloader looks for a substring the real file must contain:

FileRequired substring
litegraph.min.jsLiteGraph
litegraph.csslitegraph

The JS file's top-level namespace is LiteGraph, so the string appears in the minified bundle. The CSS file references classes like .litegraph, so its string is there too.

Atomic write. Both gates run before dest.write_bytes(data). If either fails, the file is not written — the previous (possibly working) copy is untouched. The caller sees either a completely valid file or the previous state, never a partial or corrupted download.

The mirror fallback

Two mirrors are tried for each file, in order:

  1. jsDelivr — https://cdn.jsdelivr.net/gh/jagenjo/litegraph.js@master/... Fast global CDN with a generous cache. Usually succeeds in under a second.
  2. raw.githubusercontent.com — GitHub's raw content host. Slower but rarely blocked.

The first mirror is tried, both gates applied, and if either fails the next mirror is tried. Only when both mirrors fail does the operation report failure.

Skip logic

If the target file already exists and is at least the minimum size, the downloader skips it entirely. This makes the common case — "run the script after a fresh clone" — a no-op once the files are present.

The --force flag overrides the skip. It is used by the developer launcher's python run.py vendor command to refresh a possibly-stale copy.

Exit codes and downstream behaviour

Exit codeMeaning
0Both files are present and valid
1One or more downloads failed

A non-zero exit is not fatal. The backend's startup code treats a missing vendor file as a warning, and the graph editor falls back to loading LiteGraph from jsDelivr at runtime. The user sees a working editor with a slightly slower first load.

Manual fallback

If all mirrors fail — an unusual network, an aggressive firewall — the downloader prints the exact URLs and the destination paths. Downloading the two files by hand and dropping them into web/vendor/ works identically.

backend/main.py (lifespan)On startup, if the files are missing

run.py setupDeveloper workflow
run.py vendorForce-refresh workflow

Shell Wrappers

Two shell scripts wrap the vendor download. They exist for three specific scenarios and are otherwise redundant with the Python version.

When to use them

1. Python is unavailable

A bare Linux container with curl but no Python yet. The user wants to vendor LiteGraph before installing Python — for example, as the first step of a build script that will then apt install python3.

2. Provisioning scripts

A CI runner or a cloud-init script might prefer bash scripts/download_vendor.sh over invoking Python. The bash version has no dependency on the Python installation path or version.

3. Debugging

The shell versions have no Python overhead, and curl's output is visible inline. When diagnosing a network issue — a proxy rewriting content, a firewall blocking jsDelivr — the shell version tells you exactly what curl saw.

When not to use them

For normal use, prefer python scripts/download_vendor.py. The Python version has better validation, mirror fallback, and cross-platform consistency. The shell wrappers are a fallback, not a replacement.

Feature comparison

Feature download_vendor.py download_vendor.sh download_vendor.ps1
Mirror fallback ✅ ✅ ✅
Size validation ✅ ✅ ✅
Content substring check ✅ ❌ ❌
Cross-platform ✅ Unix only Windows only
No Python dependency ❌ ✅ ✅
Verbose failure output ✅ Partial Partial

The two shell versions validate size only. They do not check the file's content, because curl and Invoke-WebRequest do not have a built-in way to search a file for a substring without extra tooling.

The .sh version in detail

Uses curl with two flags that matter:

  • -f — fail on HTTP error codes. Without this, curl writes the error page body to the output file and exits 0.
  • -sSL — silent, show errors, follow redirects. 
curl -fsSL --max-time 60 "$primary" -o "$dest"

The script checks that curl is installed before doing anything, and prints the Python alternative if it is missing: 

if ! command -v curl >/dev/null 2>&1; then
    echo "Error: curl is not installed." >&2
    echo "Install it with your package manager, or run:" >&2
    echo "    python scripts/download_vendor.py" >&2
    exit 1
fi

The .ps1 version in detail

Uses Invoke-WebRequest with -UseBasicParsing. The flag matters because on older PowerShell versions, the default parser tries to load the Windows Internet Explorer COM object — which fails on Server Core and in restricted environments. 

Invoke-WebRequest -Uri $Primary -OutFile $Dest -UseBasicParsing

The #Requires -Version 5.0 directive at the top ensures the script fails early and clearly on PowerShell 4 or earlier, rather than hitting a syntax error three lines in.

Running the .ps1 under execution policy

PowerShell by default refuses to run unsigned scripts. Bypass the policy for a single invocation: 

powershell -ExecutionPolicy Bypass -File scripts\download_vendor.ps1

Or for the current session only: 

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\download_vendor.ps1

Do not use Unrestricted at the machine or user scope — it affects every script on the system.

Both accept a --force flag

bash scripts/download_vendor.sh --force
powershell -ExecutionPolicy Bypass -File scripts\download_vendor.ps1 -Force

Without --force, a file that already exists and is at least the minimum size is skipped.

Exit codes

CodeMeaning
0Both files present and valid
1Failure — curl missing, download failed, or file too small

doc

llama_cpp_runner

Some builds of llama_cpp.server silently drop the --port command-line flag and fall back to uvicorn's default of 8000 — which collides with the backend's own port. Setting LLAMA_CPP_PORT in the environment does not help in those builds either.

This script bypasses the module's argument parser entirely. It reads configuration from environment variables, constructs the settings objects directly, and calls uvicorn.run() with an explicit port.

The port collision problem

The backend listens on port 8000 by default. If llama_cpp.server also defaults to 8000, the second process to bind fails with Address already in use — or worse, succeeds on a different interface and the two servers fight over requests.

The backend's llama_server.py passes --port 8080 when spawning the module. On the builds where that flag is dropped, the module still tries 8000. The runner avoids the whole problem by not relying on the module's command-line interface at all.

Model ID resolution

The server exposes the value of ModelSettings.model as the model ID in /v1/models, and requires the same string back in the model field of chat and embeddings requests.

The runner resolves the model path to an absolute path before constructing ModelSettings. The backend's llm.py resolves the same path before sending requests, so the two agree.

Chat format handling

This is the part that surprises people.

If LLAMA_CPP_CHAT_FORMAT is set to a non-empty value, it is passed to ModelSettings and overrides the model's embedded chat template. This is usually the wrong thing to do — nearly every modern GGUF ships its own template in tokenizer.chat_template, and forcing a different one causes the model to produce garbage or an immediate EOS token.

If LLAMA_CPP_CHAT_FORMAT is empty (or unset), the runner does not pass chat_format to ModelSettings. The model's embedded template is used automatically, which is correct for Llama-3.2, Qwen, Mistral, Gemma, and every other modern model.

Set LLAMA_CPP_CHAT_FORMAT only when you know you need it. The default of "empty = use the model's own template" is correct for almost every model released in the last two years. Overriding it is a deliberate choice, not a convenience.

Settings construction robustness

The llama_cpp.server.settings module has changed its field set across versions. A runner that assumes a specific version breaks on the next release. This runner tolerates variation: 

def _build_model_settings(ModelSettings, kwargs: dict):
    """Construct ModelSettings, tolerating field-set variations."""
    try:
        return ModelSettings(**kwargs)
    except TypeError:
        minimal = {"model": kwargs["model"]}
        ms = ModelSettings(**minimal)
        for key, value in kwargs.items():
            if key == "model":
                continue
            try:
                setattr(ms, key, value)
            except Exception:
                pass
        return ms

It first tries the straightforward constructor. If that raises TypeError — meaning some field is not recognized — it constructs a minimal object and sets each additional field individually, ignoring ones that fail.

create_app invocation patterns

The create_app function has changed its signature more than once. The runner tries six different calling conventions, from most likely to least:

PatternCall shape
list-kwargcreate_app(model_settings=[ms], server_settings=ss)
dict-kwargcreate_app(model_settings={ms.model: ms}, server_settings=ss)
list-positionalcreate_app([ms], ss)
single-kwargcreate_app(model_settings=ms, server_settings=ss)
single-positionalcreate_app(ms, ss)
list-onlycreate_app([ms])

The first that succeeds wins. If all six raise, the runner reports a clear error and exits non-zero.

sessions.db — the runtime SQLite file

Not a script, but documented here because it is one of the runtime artifacts the scripts manage and the backend writes to. sessions.db is created by backend/storage.py on the first run of the backend and lives at the project root.

It is not committed to git: 

*.db
*.sqlite
*.sqlite3

What is in the file

Two tables:

Table Purpose Populated by
sessions Conversation history, one row per session_id Chat routes when a session_id is provided
graph_runs Graph execution history with full event streams /api/graph/run and /ws/graph after each run

File lifecycle

First backend start:
    backend/storage.py::SessionStore.init()
        → opens sessions.db
        → CREATE TABLE IF NOT EXISTS sessions (...)
        → CREATE TABLE IF NOT EXISTS graph_runs (...)
        → CREATE INDEX IF NOT EXISTS ...
        → closes

First chat with session_id:
    POST /api/chat
        → agent.run(...)
        → agent.store.save(session_id, messages)
        → opens sessions.db
        → INSERT INTO sessions ... ON CONFLICT UPDATE
        → closes

First graph run:
    POST /api/graph/run
        → engine.execute(...)
        → routes._summarize_events(events)
        → store.save_run(payload, events, status, final_text)
        → opens sessions.db
        → INSERT INTO graph_runs ...
        → DELETE older runs beyond max_graph_runs
        → closes

Every method opens a fresh connection, executes, and closes. This is the "no connection pool" pattern — it is slightly less efficient but sidesteps every "database is locked" scenario. SQLite's single-writer semantics are respected automatically.

Where the file lives

The path is configured in .env: 

AGENT_SESSION_DB=sessions.db

A bare filename resolves relative to the process working directory — which is the project root when the backend is launched via run.py, start.sh, or scripts/serve.py. An absolute path passes through unchanged.

Inspecting the file

To inspect the database manually with the portable SQLite CLI: 

# List tables
runtime/sqlite/sqlite3 sessions.db ".tables"

# Count sessions
runtime/sqlite/sqlite3 sessions.db "SELECT COUNT(*) FROM sessions;"

# Show the newest session
runtime/sqlite/sqlite3 sessions.db \
    "SELECT id, updated_at FROM sessions ORDER BY updated_at DESC LIMIT 5;"

# Show recent graph runs
runtime/sqlite/sqlite3 sessions.db \
    "SELECT id, graph_name, status, finished_at FROM graph_runs ORDER BY finished_at DESC LIMIT 5;"

Or with the system sqlite3: 

sqlite3 sessions.db ".tables"

Resetting

To clear all conversation and graph-run history without touching the rest of the application: 

rm sessions.db
# The next backend start recreates it empty.

Or keep the schema and clear only the data:

sqlite3 sessions.db "DELETE FROM sessions; DELETE FROM graph_runs;"

Size estimates

Data Per row 1000 rows
Session (typical 20-message chat) 5–20 KB 5–20 MB
Graph run (typical 20-event execution) 2–15 KB 2–15 MB

The max_graph_runs config caps graph-runs growth at 100 rows by default. Session growth is unbounded — but a session is only one row no matter how many turns it has, so the file grows with the number of distinct sessions, not the number of messages.

This is user data. Unlike the runtime/ folder, deleting sessions.db is not recoverable. Back it up before resetting if the history matters.

Backup

A direct cp is unsafe under WAL mode — it can miss un-checkpointed writes. Use the SQLite CLI's .backup command for a consistent snapshot: 

runtime/sqlite/sqlite3 sessions.db ".backup sessions-backup.db"

Troubleshooting

MCP handshake fails on Windows with "Connection closed"

The classic Proactor-vs-Selector bug. The MCP SDK is reading from a subprocess pipe and hitting a known Windows asyncio issue.

Fix: launch the backend via scripts/serve.py (or any launcher that calls it) rather than importing uvicorn directly. The script sets the event loop policy before uvicorn creates its loop.

If you are already using serve.py and still see this error, the most likely cause is that a tool module in mcp_server/tools/ is printing to stdout during import. Search the folder for print( — there should be zero hits.

"ModuleNotFoundError: No module named 'backend'"

Only happens with --reload. The reloader's child process does not have the project root on its sys.path.

Fix: serve.py sets both sys.path and PYTHONPATH at module top, before uvicorn imports anything. On Windows, only the environment variable survives the multiprocessing spawn — which is why both are set.

If the error persists, check that PYTHONPATH is actually being exported. Run: 

> set PYTHONPATH
> python scripts\serve.py

Thousands of "GET /api/health 200" lines in the log

Uvicorn's access log. The web UI polls several endpoints every few seconds.

Fix: leave AGENT_UVICORN_ACCESS_LOG at its default of 0. If you have explicitly set it to 1 and want to disable it, change it back.

download_vendor.py reports "archive is too small"

The size gate fired. Either:

  • A captive portal or proxy returned an HTML login page instead of the JS/CSS file.
  • jsDelivr is serving a truncated response (rare, but it happens during CDN failovers).
  • The fallback mirror (raw.githubusercontent.com) is returning a GitHub error page.

Check:

curl -I https://cdn.jsdelivr.net/gh/jagenjo/litegraph.js@master/build/litegraph.min.js
HTTP/2 200
content-type: application/javascript; charset=utf-8
content-length: 87432

If content-type is text/html, you are behind a login wall. Configure your proxy or use a different network.

download_vendor.py reports "does not contain 'LiteGraph'"

The size gate passed but the content gate did not. Something served a file of the right size that is not the real LiteGraph bundle.

A common cause: a corporate proxy that replaces JS files with its own "site blocked" page. The page happens to be at least 50 KB because it embeds CSS and images.

Fix: download the files manually from a network the proxy does not intercept, and drop them into web/vendor/. The downloader will then skip them on the next run.

Graph editor loads with CDN warning

The vendor files are missing from web/vendor/, and the editor is loading LiteGraph from jsDelivr at runtime.

This is not an error — it is a designed fallback. To fix it permanently: 

python scripts/download_vendor.py

Or on a network where Python is not available: 

bash scripts/download_vendor.sh

llama_cpp_runner exits with code 2

LLAMA_CPP_MODEL is unset, or the file it points to does not exist. The runner prints the resolved path in its first log line — check that the path is what you expect: 

[llama_cpp_runner] resolved model path: C:\...\models\my-model.gguf
[llama_cpp_runner] model file does not exist: C:\...\models\my-model.gguf

Relative paths are resolved against the runner's working directory, which is the project root when the backend spawns it. Running the runner from a different folder changes the resolution.

llama_cpp_runner exits with code 5

create_app failed for all six calling conventions. This means the installed llama-cpp-python has a signature the runner does not know about.

The runner logs every attempt: 

[llama_cpp_runner] create_app pattern 'list-kwarg' raised TypeError: ...
[llama_cpp_runner] create_app pattern 'dict-kwarg' raised TypeError: ...
...

The exception from the last attempt is the most informative. In practice this happens when a very old or very new version of llama-cpp-python is installed. Upgrading or downgrading to the version pinned in requirements.txt resolves it.

llama-cpp server starts on port 8000 instead of 8080

The module's argument parser dropped the --port flag. This is the bug the runner exists to fix.

If the backend is spawning the module directly (not via the runner), check backend/llama_server.py's _build_python_command. It should be calling scripts/llama_cpp_runner.py, not -m llama_cpp.server.

Backend starts but llama-cpp is idle

The runner could not load a model. Check the backend log: 

[llama_cpp_runner] LLAMA_CPP_MODEL is required

Or: 

[llama_cpp_runner] model file does not exist: ...

Set AGENT_LLAMA_CPP_MODEL in .env to a filename that exists in models/, or drop a .gguf file into models/ with the configured name.

Model produces garbage output

Almost always a chat format mismatch. The runner uses the model's own embedded template by default, which is correct for modern models. If you have set LLAMA_CPP_CHAT_FORMAT explicitly, unset it: 

LLAMA_CPP_CHAT_FORMAT=

#!/usr/bin/env python3
"""
3olution Agent Graph — uvicorn entry point.
https://3olution.com

This module exists because launching uvicorn directly has three
problems that are easy to miss and hard to diagnose:

    1. Windows event loop
    2. sys.path for the reloader child
    3. Access log noise

================================================================
  PROBLEM 1: WINDOWS EVENT LOOP
================================================================

  On Windows, the MCP SDK's stdio transport requires
  ProactorEventLoop to spawn subprocesses. But ProactorEventLoop
  on Python 3.8+ has a known quirk: it cannot reliably read from
  the subprocess's pipes, causing the MCP handshake to randomly
  hang or fail.

  The correct policy for a process that spawns subprocesses AND
  reads from their pipes is SelectorEventLoop. But Selector does
  not implement create_subprocess_exec, which uvicorn itself
  needs... except it doesn't, not for the default HTTP/WebSocket
  transports. Those use sockets, which Selector handles fine.

  The MCP SDK v2+ handles this internally by dispatching
  subprocess creation through its own thread pool, so it works
  under either policy. But the fix for the general case is to set
  Selector early — before uvicorn imports its asyncio loop.

  We set it here, at the top of this module, before importing
  uvicorn. Setting it inside backend/main.py is too late: uvicorn
  creates its loop before it imports the app.

================================================================
  PROBLEM 2: sys.path FOR THE RELOADER CHILD
================================================================

  Running `python scripts/serve.py` puts scripts/ on sys.path[0],
  not the project root. When uvicorn (with --reload) spawns a
  child process, that child re-imports backend.main, which fails
  with ModuleNotFoundError because the project root is not on
  sys.path.

  Two things are needed:

    - sys.path in THIS process (for direct imports)
    - PYTHONPATH in the environment (for the child process)

  Windows uses `multiprocessing` spawn for the reloader child,
  which does NOT inherit sys.path mutations from the parent. Only
  the environment variable survives.

================================================================
  PROBLEM 3: ACCESS LOG NOISE
================================================================

  Uvicorn's per-request access log is verbose. The web UI polls
  /api/health, /api/ollama/ps, and /api/llama/runtime/status every
  few seconds while a page is open. In a four-hour session that is
  thousands of identical log lines — a real problem for the
  desktop log dock and the rotating file sink.

  Access logging is disabled by default here. Re-enable by setting
  AGENT_UVICORN_ACCESS_LOG=1 in .env.

================================================================
  USAGE
================================================================

  From the command line:

      python scripts/serve.py

  Or via the developer launcher:

      python run.py backend

  Or via the portable launcher:

      ./start.sh          # Linux / macOS
      start.bat           # Windows

  Or directly with uvicorn (bypasses this file's fixes):

      uvicorn backend.main:app --reload

  Environment variables read:

      AGENT_HOST                  bind address (default 127.0.0.1)
      AGENT_PORT                  bind port (default 8000)
      AGENT_RELOAD                "1" to enable --reload (default "0")
      AGENT_LOG_LEVEL             uvicorn log level (default "info")
      AGENT_UVICORN_ACCESS_LOG    "1" to enable access log (default "0")
"""

from __future__ import annotations

import asyncio
import os
import sys
from pathlib import Path


# ══════════════════════════════════════════════════════════════════════
#  Fix 1 — make `backend` importable
# ══════════════════════════════════════════════════════════════════════
#
#  Must run BEFORE importing uvicorn (which imports the app).

PROJECT_ROOT = Path(__file__).resolve().parent.parent
_root_str = str(PROJECT_ROOT)

# sys.path — for imports in this process.
if _root_str not in sys.path:
    sys.path.insert(0, _root_str)

# PYTHONPATH — for the reloader child process.
# Windows multiprocessing spawn does not inherit sys.path mutations,
# only the environment.
_existing_pp = os.environ.get("PYTHONPATH", "")
if _root_str not in _existing_pp.split(os.pathsep):
    os.environ["PYTHONPATH"] = (
        _root_str + (os.pathsep + _existing_pp if _existing_pp else "")
    )


# ══════════════════════════════════════════════════════════════════════
#  Fix 2 — Windows event loop policy
# ══════════════════════════════════════════════════════════════════════
#
#  Set this BEFORE importing uvicorn. uvicorn will pick up the
#  policy when it creates its loop.

if sys.platform == "win32":
    # SelectorEventLoop has reliable pipe reading, which the MCP
    # SDK's stdio transport depends on. The MCP SDK dispatches
    # subprocess creation internally so it does not need Proactor.
    asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())


# ══════════════════════════════════════════════════════════════════════
#  Now it is safe to import uvicorn
# ══════════════════════════════════════════════════════════════════════

import uvicorn  # noqa: E402


# ══════════════════════════════════════════════════════════════════════
#  Configuration
# ══════════════════════════════════════════════════════════════════════

HOST = os.environ.get("AGENT_HOST", "127.0.0.1")
PORT = int(os.environ.get("AGENT_PORT", "8000"))
RELOAD = os.environ.get("AGENT_RELOAD", "0") == "1"
LOG_LEVEL = os.environ.get("AGENT_LOG_LEVEL", "info").lower()

# Access log — off by default. See Problem 3 in the module docstring.
ACCESS_LOG = os.environ.get("AGENT_UVICORN_ACCESS_LOG", "0") == "1"


# ══════════════════════════════════════════════════════════════════════
#  Entry point
# ══════════════════════════════════════════════════════════════════════

def main() -> None:
    """Run uvicorn with the correct loop and the project on sys.path."""
    uvicorn.run(
        "backend.main:app",
        host=HOST,
        port=PORT,
        reload=RELOAD,
        log_level=LOG_LEVEL,
        loop="asyncio",      # honor the policy set above
        access_log=ACCESS_LOG,
        # The reloader watches only the project root, not the whole
        # filesystem. Adding .venv/ would cause reloads on every
        # pip operation.
        reload_dirs=[str(PROJECT_ROOT)] if RELOAD else None,
    )


if __name__ == "__main__":
    main()

#!/usr/bin/env python3
"""
3olution Agent Graph — cross-platform LiteGraph.js vendor downloader.
https://3olution.com

Downloads the two LiteGraph.js files the graph editor needs into
`web/vendor/`. Uses only the Python standard library, so it runs on
any Python 3.8+ installation without extra dependencies.

================================================================
  WHAT IT DOWNLOADS
================================================================

  Two files from the jagenjo/litegraph.js repository:

      build/litegraph.min.js    → web/vendor/litegraph.min.js
      css/litegraph.css         → web/vendor/litegraph.css

  These files are NOT committed to git (see .gitignore). They are
  fetched on demand by:

      - scripts/serve.py          (on startup, if missing)
      - backend/main.py           (in lifespan, if missing)
      - run.py setup              (developer workflow)
      - run.py vendor             (force refresh)
      - start.sh / start.bat      (portable workflow)

================================================================
  MIRRORS
================================================================

  Two mirrors are tried for each file, in order:

      1. jsDelivr (fast global CDN, generous cache)
      2. raw.githubusercontent.com (GitHub direct)

  The first mirror usually succeeds. The second exists for
  environments where jsDelivr is blocked or slow.

================================================================
  VALIDATION
================================================================

  Each downloaded file is validated before being written to disk:

    - Minimum size: a 404 HTML page is only a few KB, so a size
      floor rejects error pages. The JS minimum is 50 KB; the CSS
      minimum is 1 KB.
    - Required substring: the JS file must contain "LiteGraph"; the
      CSS file must contain "litegraph". This catches cases where
      a proxy returns a generic 200 page instead of the real file.

  Only after both checks pass is the file moved into place. A
  partial or corrupted download never overwrites a working file.

================================================================
  USAGE
================================================================

    python scripts/download_vendor.py
        Download both files into web/vendor/.

    python scripts/download_vendor.py --force
        Re-download even if the files already exist.

    python scripts/download_vendor.py --quiet
        Suppress per-file progress output. Used by scripts that
        invoke this programmatically.

  The exit code is 0 if both files are present after the run, and
  1 if any file could not be downloaded. The caller can decide
  whether that is fatal — in practice, the graph editor falls back
  to loading LiteGraph from jsDelivr at runtime, so a failed
  download is not catastrophic.

================================================================
  EXIT CODES
================================================================

    0   both files are present
    1   one or more downloads failed
"""

from __future__ import annotations

import argparse
import sys
import urllib.error
import urllib.request
from pathlib import Path


# ══════════════════════════════════════════════════════════════════════
#  Paths and constants
# ══════════════════════════════════════════════════════════════════════

ROOT = Path(__file__).resolve().parent.parent
VENDOR = ROOT / "web" / "vendor"

# Each entry: filename -> list of mirror URLs (tried in order).
FILES: dict[str, list[str]] = {
    "litegraph.min.js": [
        "https://cdn.jsdelivr.net/gh/jagenjo/litegraph.js@master/build/litegraph.min.js",
        "https://raw.githubusercontent.com/jagenjo/litegraph.js/master/build/litegraph.min.js",
    ],
    "litegraph.css": [
        "https://cdn.jsdelivr.net/gh/jagenjo/litegraph.js@master/css/litegraph.css",
        "https://raw.githubusercontent.com/jagenjo/litegraph.js/master/css/litegraph.css",
    ],
}

# Minimum plausible size in bytes; anything smaller is a failed download.
MIN_SIZE: dict[str, int] = {
    "litegraph.min.js": 50_000,   # ~85 KB in practice
    "litegraph.css": 1_000,       # ~4 KB in practice
}

# A sanity-check substring that must appear in the file's content.
REQUIRED_SUBSTRING: dict[str, str] = {
    "litegraph.min.js": "LiteGraph",
    "litegraph.css": "litegraph",
}

# Network timeout for individual requests.
TIMEOUT_SECONDS = 30.0


# ══════════════════════════════════════════════════════════════════════
#  Quiet helper
# ══════════════════════════════════════════════════════════════════════

class _Logger:
    """Print messages unless --quiet is set."""

    def __init__(self, quiet: bool) -> None:
        self.quiet = quiet

    def __call__(self, msg: str = "") -> None:
        if not self.quiet:
            print(msg)


# ══════════════════════════════════════════════════════════════════════
#  Downloader
# ══════════════════════════════════════════════════════════════════════

def _download_one(
    name: str,
    urls: list[str],
    force: bool,
    log: _Logger,
) -> bool:
    """
    Download a single file, trying each mirror in order.

    Returns True on success, False on failure. Never raises.
    """
    dest = VENDOR / name

    # Skip if the file already looks good.
    if dest.exists() and not force:
        size = dest.stat().st_size
        if size >= MIN_SIZE[name]:
            log(f"  ✓ {name} already present ({size:,} bytes) — skipping")
            return True
        log(
            f"  ! {name} present but suspiciously small "
            f"({size} bytes) — re-downloading"
        )

    last_error: Exception | None = None

    for url in urls:
        try:
            log(f"  → Downloading {name}")
            log(f"      from {url}")

            req = urllib.request.Request(
                url,
                headers={"User-Agent": "3olution-setup/1.0 (+https://3olution.com)"},
            )
            with urllib.request.urlopen(req, timeout=TIMEOUT_SECONDS) as response:
                data = response.read()

            # Size check.
            if len(data) < MIN_SIZE[name]:
                raise ValueError(
                    f"downloaded file is too small "
                    f"({len(data)} bytes < {MIN_SIZE[name]} bytes)"
                )

            # Content check.
            text = data.decode("utf-8", errors="replace")
            if REQUIRED_SUBSTRING[name] not in text:
                raise ValueError(
                    f"downloaded file does not contain "
                    f"'{REQUIRED_SUBSTRING[name]}' — wrong URL?"
                )

            # Write only after both checks pass.
            dest.write_bytes(data)
            log(f"  ✓ {name} ({len(data):,} bytes)")
            return True

        except (
            urllib.error.URLError,
            urllib.error.HTTPError,
            ValueError,
            TimeoutError,
            OSError,
        ) as exc:
            last_error = exc
            log(f"      ✗ failed: {exc}")
            continue

    log(f"  ✗ {name}: all mirrors failed ({last_error})")
    return False


def download_all(force: bool = False, quiet: bool = False) -> bool:
    """
    Download every vendor file.

    Returns True if all files were downloaded successfully, False
    otherwise.
    """
    log = _Logger(quiet)
    VENDOR.mkdir(parents=True, exist_ok=True)
    log(f"Vendor directory: {VENDOR}")

    ok = True
    for name, urls in FILES.items():
        if not _download_one(name, urls, force, log):
            ok = False
    return ok


# ══════════════════════════════════════════════════════════════════════
#  Manual instructions
# ══════════════════════════════════════════════════════════════════════

def _print_manual_instructions() -> None:
    """Print fallback instructions for a failed download."""
    print()
    print("Manual fallback: download these two files into web/vendor/:")
    for name, urls in FILES.items():
        print(f"  {name}:")
        for u in urls:
            print(f"    {u}")
    print()
    print("Place both files at:")
    print(f"  {VENDOR / 'litegraph.min.js'}")
    print(f"  {VENDOR / 'litegraph.css'}")


# ══════════════════════════════════════════════════════════════════════
#  CLI
# ══════════════════════════════════════════════════════════════════════

def parse_args() -> argparse.Namespace:
    p = argparse.ArgumentParser(
        description=(
            "Download LiteGraph.js vendor files for the 3olution Agent Graph."
        ),
    )
    p.add_argument(
        "--force", action="store_true",
        help="Re-download even if the files already exist.",
    )
    p.add_argument(
        "--quiet", action="store_true",
        help="Suppress per-file progress output.",
    )
    return p.parse_args()


def main() -> int:
    args = parse_args()

    ok = download_all(force=args.force, quiet=args.quiet)

    if not args.quiet:
        print()
        if ok:
            print("All vendor files present.")
        else:
            print("Some downloads failed.")
            _print_manual_instructions()

    return 0 if ok else 1


if __name__ == "__main__":
    sys.exit(main())

}

scripts/llama_cpp_runner.py
— 
"""
Direct runner for llama-cpp-python's OpenAI-compatible server.
https://3olution.com

Why this exists
---------------

Some builds of `llama_cpp.server` silently drop the `--port` command
line flag and fall back to uvicorn's default of 8000, which collides
with the backend's own port. Setting the LLAMA_CPP_PORT environment
variable does not help in those builds either.

This script bypasses the module's argument parser entirely. It reads
configuration from environment variables, constructs the settings
objects directly, and calls `uvicorn.run()` with an explicit port.

Model ID resolution
-------------------

The server exposes the value of `ModelSettings.model` as the model ID
in `/v1/models`, and requires the same string back in the `model` field
of chat and embeddings requests. This runner resolves the model path to
an absolute path before constructing ModelSettings. backend/llm.py
resolves the same path before sending requests, so the two agree.

Chat format handling
--------------------

If LLAMA_CPP_CHAT_FORMAT is set to a non-empty value, it is passed to
ModelSettings and OVERRIDES the model's embedded chat template. This
is usually the wrong thing to do — nearly every modern GGUF ships its
own template in `tokenizer.chat_template`, and forcing a different one
causes the model to produce garbage or an immediate EOS token.

If LLAMA_CPP_CHAT_FORMAT is empty (or unset), this runner does NOT
pass `chat_format` to ModelSettings. The model's embedded template is
used automatically, which is correct for Llama-3.2, Qwen, Mistral,
Gemma, and every other modern model.

Set LLAMA_CPP_CHAT_FORMAT explicitly only when the GGUF has no
embedded template, or when you deliberately want to override it.

Environment variables read
--------------------------

    LLAMA_CPP_MODEL           Absolute or relative path to .gguf (required)
    LLAMA_CPP_HOST            Bind address (default 127.0.0.1)
    LLAMA_CPP_PORT            Bind port    (default 8081)
    LLAMA_CPP_N_CTX           Context window (default 4096)
    LLAMA_CPP_N_GPU_LAYERS    GPU layers   (default 0)
    LLAMA_CPP_CHAT_FORMAT     Chat format  (default: empty = use model's own)
    LLAMA_CPP_API_KEY         Optional API key
    LLAMA_CPP_EMBEDDING       "true" to enable /v1/embeddings
"""

from __future__ import annotations

import inspect
import os
import sys


# ══════════════════════════════════════════════════════════════════════
#  Environment helpers
# ══════════════════════════════════════════════════════════════════════

def _int_env(name: str, default: int) -> int:
    raw = os.environ.get(name)
    if raw is None or raw == "":
        return default
    try:
        return int(raw)
    except ValueError:
        return default


def _bool_env(name: str, default: bool = False) -> bool:
    raw = os.environ.get(name)
    if raw is None:
        return default
    return raw.strip().lower() in ("1", "true", "yes", "on")


def _str_env(name: str, default: str = "") -> str:
    """Return the env var value with surrounding whitespace stripped."""
    return (os.environ.get(name) or default).strip()


def _log(msg: str) -> None:
    print(f"[llama_cpp_runner] {msg}", file=sys.stderr, flush=True)


# ══════════════════════════════════════════════════════════════════════
#  Settings construction
# ══════════════════════════════════════════════════════════════════════

def _build_model_settings(ModelSettings, kwargs: dict):
    """Construct ModelSettings, tolerating field-set variations."""
    try:
        return ModelSettings(**kwargs)
    except TypeError:
        minimal = {"model": kwargs["model"]}
        ms = ModelSettings(**minimal)
        for key, value in kwargs.items():
            if key == "model":
                continue
            try:
                setattr(ms, key, value)
            except Exception:
                pass
        return ms


def _build_server_settings(ServerSettings, host: str, port: int):
    """Construct ServerSettings with the requested host and port."""
    try:
        return ServerSettings(host=host, port=port)
    except Exception:
        pass

    try:
        ss = ServerSettings()
        try:
            ss.host = host  # type: ignore[attr-defined]
        except Exception:
            pass
        try:
            ss.port = port  # type: ignore[attr-defined]
        except Exception:
            pass
        return ss
    except Exception:
        pass

    try:
        return ServerSettings()
    except Exception:
        return None


# ══════════════════════════════════════════════════════════════════════
#  create_app invocation
# ══════════════════════════════════════════════════════════════════════

def _call_create_app(create_app, model_settings, server_settings):
    """Call create_app with the argument shape its signature expects."""
    try:
        sig = inspect.signature(create_app)
        _log(f"create_app signature: {sig}")
    except Exception:
        pass

    patterns = [
        (
            "list-kwarg",
            lambda: create_app(
                model_settings=[model_settings],
                server_settings=server_settings,
            ),
        ),
        (
            "dict-kwarg",
            lambda: create_app(
                model_settings={model_settings.model: model_settings},
                server_settings=server_settings,
            ),
        ),
        (
            "list-positional",
            lambda: create_app([model_settings], server_settings),
        ),
        (
            "single-kwarg",
            lambda: create_app(
                model_settings=model_settings,
                server_settings=server_settings,
            ),
        ),
        (
            "single-positional",
            lambda: create_app(model_settings, server_settings),
        ),
        (
            "list-only",
            lambda: create_app([model_settings]),
        ),
    ]

    last_exc: Exception | None = None
    for name, fn in patterns:
        try:
            app = fn()
            _log(f"create_app succeeded via '{name}'")
            return app
        except TypeError as exc:
            last_exc = exc
            _log(f"create_app pattern '{name}' raised TypeError: {exc}")
            continue
        except Exception as exc:
            last_exc = exc
            _log(f"create_app pattern '{name}' raised {type(exc).__name__}: {exc}")
            continue

    assert last_exc is not None
    raise last_exc


# ══════════════════════════════════════════════════════════════════════
#  Main
# ══════════════════════════════════════════════════════════════════════

def main() -> int:
    # ── Import SDK pieces ────────────────────────────────────────────
    try:
        from llama_cpp.server.app import create_app
        from llama_cpp.server.settings import ModelSettings, ServerSettings
    except ImportError as exc:
        _log(f"llama-cpp-python is not installed or is broken: {exc}")
        return 1

    # ── Resolve model path ───────────────────────────────────────────
    model_path_raw = _str_env("LLAMA_CPP_MODEL")
    if not model_path_raw:
        _log("LLAMA_CPP_MODEL is required")
        return 2

    model_path = os.path.abspath(model_path_raw)
    _log(f"resolved model path: {model_path}")

    if not os.path.isfile(model_path):
        _log(f"model file does not exist: {model_path}")
        return 2

    # ── Read remaining configuration ─────────────────────────────────
    host = _str_env("LLAMA_CPP_HOST", "127.0.0.1")
    port = _int_env("LLAMA_CPP_PORT", 8081)
    n_ctx = _int_env("LLAMA_CPP_N_CTX", 4096)
    n_gpu_layers = _int_env("LLAMA_CPP_N_GPU_LAYERS", 0)
    api_key = _str_env("LLAMA_CPP_API_KEY") or None
    embedding = _bool_env("LLAMA_CPP_EMBEDDING", False)

    # Chat format is optional. Empty means "use the model's own
    # embedded template". Only pass it through when explicitly set.
    chat_format = _str_env("LLAMA_CPP_CHAT_FORMAT")

    _log(f"host={host} port={port}")
    _log(f"n_ctx={n_ctx} n_gpu_layers={n_gpu_layers}")
    if chat_format:
        _log(f"chat_format={chat_format} (explicit override)")
    else:
        _log("chat_format=(unset — using model's embedded template)")
    _log(f"embedding={embedding}")

    # ── ModelSettings ────────────────────────────────────────────────
    model_kwargs: dict = {
        "model": model_path,
        "n_ctx": n_ctx,
        "n_gpu_layers": n_gpu_layers,
    }
    if chat_format:
        model_kwargs["chat_format"] = chat_format
    if api_key:
        model_kwargs["api_key"] = api_key
    if embedding:
        model_kwargs["embedding"] = True

    try:
        model_settings = _build_model_settings(ModelSettings, model_kwargs)
    except Exception as exc:
        _log(f"ModelSettings construction failed: {exc}")
        return 3

    # ── ServerSettings ───────────────────────────────────────────────
    server_settings = _build_server_settings(ServerSettings, host, port)
    if server_settings is None:
        _log("ServerSettings could not be constructed; continuing without it")

    # ── Build the app ────────────────────────────────────────────────
    try:
        if server_settings is not None:
            app = _call_create_app(create_app, model_settings, server_settings)
        else:
            app = _call_create_app(create_app, model_settings, None)
    except Exception as exc:
        _log(f"create_app failed for all patterns: {exc}")
        return 5

    # ── Run uvicorn with our explicit host and port ──────────────────
    import uvicorn

    _log(f"starting uvicorn on {host}:{port}")

    uvicorn.run(
        app,
        host=host,
        port=port,
        log_level="info",
        access_log=False,
    )
    return 0


if __name__ == "__main__":
    sys.exit(main())
